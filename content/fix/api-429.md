
或者：

```error
429 Rate limit reached for requests
```

Claude Code里的形式：

```error
API Error: Request rejected (429) · this may be a temporary capacity issue. If it persists, check https://status.claude.com.
```

## 人话：这是怎么回事

429是「请求太多了，先停一停」。但背后有两种完全不同的情况：

一种是**限速**：你每分钟发得太快、或同时发得太多，被临时拦住，等一会儿就好。报错里常有 `rate limit`、`Retry-After`。

另一种是**额度用完**：账户没余额，或达到了用量上限。重试永远不会成功，必须去充值或调整额度。OpenAI常见字样是 `insufficient_quota` 和 `You exceeded your current quota`；Anthropic官方也说明，到达用量档位的月度花费上限时会返回429，且这种情况不带 `retry-after`，会一直失败。

## 最快的解法：把这段发给AI

```prompt 复制给 Claude Code
我调用API时收到429错误：

（粘贴完整报错）

请先判断是哪一种：
A. 限速（rate limit，带Retry-After或提示稍后重试）
B. 额度/余额用完（insufficient_quota、billing、credit balance 之类）
然后：
- 如果是A：检查代码里是否有循环、并发或没有加限制的重复调用（例如页面每次渲染都在请求）；加上指数退避重试（有最大次数，尊重Retry-After），并减少不必要的调用。
- 如果是B：不要修改代码，告诉我去哪个控制台页面查看余额和限额。
特别检查：有没有"失败就无限重试"的写法，那会瞬间烧掉额度。
```

## 想自己动手的话

先区分类型：

- 看控制台（OpenAI的Billing、Anthropic Console的Plans & Billing）：余额为零或已达上限，就是第二种，充值或提高限额。注意新充值有时要几分钟生效。
- 余额充足仍然报429，是限速。放慢速度，等几十秒再试。官方建议：有 `Retry-After` 就至少等那么久；没有就用带随机间隔的指数退避，并限制重试次数。限制按组织计算，同事的使用也算在内。
- 检查是否有代码在疯狂重复请求，比如放在React组件渲染里的请求没有依赖控制，一页就能刷出几十次。

用Claude Code时，官方的排查建议：运行 `/status` 确认当前用的是哪个凭据，因为环境里残留的 `ANTHROPIC_API_KEY` 可能让请求走了低额度的密钥而不是你的订阅。想知道订阅额度，看 [claude-usage-limit](/fix/claude-usage-limit)。

> [!warn] 让AI写「出错就自动重试」时一定要限制次数和间隔。无限重试遇到额度用完的429，会在几分钟内空转出一堆无效请求，有的按量计费的服务还会因此产生费用。

## 下次怎么避免

在服务商后台设置月度预算提醒或上限。开发阶段用小模型、小数据测试。有批量任务时让AI加队列和并发上限。
