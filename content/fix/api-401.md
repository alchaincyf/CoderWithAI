```error
401 Incorrect API key provided: sk-proj-********abcd. You can find your API key at https://platform.openai.com/account/api-keys.
```

Anthropic（Claude）接口的同类错误长这样：

```error
{"type":"error","error":{"type":"authentication_error","message":"invalid x-api-key"}}
```

Claude Code里则显示为：

```error
Invalid API key · Fix external API key
```

## 人话：这是怎么回事

401的意思是「身份验证没通过」：服务器收到了你的请求，但不认你出示的 [API Key](/words/api-key)。Anthropic官方列出的原因是密钥格式错误、已被撤销或已过期。

对新手来说，更常见的原因是：**密钥根本没传对**。比如 `.env` 没被读取、变量名拼错、复制时带了空格或换行、用了别家的密钥，或者改完 `.env` 没重启程序。

## 最快的解法：把这段发给AI

```prompt 复制给 Claude Code
我的程序调用API时报401认证错误：

（把报错原文粘贴到这里，注意把密钥本身打码）

请排查，不要在回复里打印出密钥的完整内容：
1. 检查代码是怎么读取密钥的（环境变量名是什么），以及 .env 文件的位置、变量名是否一致、有没有引号或多余空格/换行。
2. 在代码里临时输出"密钥是否存在、长度多少、前4位是什么"（不输出完整密钥），确认程序真的读到了。
3. 确认密钥和接口地址是同一家：OpenAI的sk-开头密钥不能用于Claude，反之亦然；用了中转或国内模型平台的话，base URL和密钥也要配套。
4. 检查是否需要重启开发服务器。排查完删掉临时调试输出。
```

## 想自己动手的话

按这个清单一项项排除：

1. 密钥有没有粘贴完整，前后有没有空格或换行。
2. `.env` 里的变量名和代码里读的名字是否一致（区分大小写）。
3. 改了 `.env` 之后，**重启**开发服务器；部署在线上的，要在平台里配 [环境变量](/words/env-var) 并重新部署，见 [env-missing-in-production](/fix/env-missing-in-production)。
4. 去服务商控制台确认密钥还在、没被删除或停用，必要时新建一个。
5. 用的是不是别家的密钥，或者地址指向了别家的接口。

如果是 Claude Code 本身报错，在终端里检查有没有残留的环境变量：

```bash
env | grep ANTHROPIC
```

这条命令列出名字带 ANTHROPIC 的环境变量。官方的建议是：取消设置 `ANTHROPIC_API_KEY` 后运行 `/login` 改用订阅登录，并用 `/status` 确认实际在用哪个凭据。

> [!warn] 不要把完整密钥粘贴到聊天里、截图里或提交到GitHub。如果已经暴露，立刻去控制台作废，见 [secret-leaked](/fix/secret-leaked)。

## 下次怎么避免

密钥统一放 `.env`，用 `.env.example` 记录变量名。新建密钥后先用一条最简单的请求验证，再接进项目。

## 还不行？

如果是 429，看 [api-429](/fix/api-429)；503/529 看 [api-overloaded](/fix/api-overloaded)。把变量名、读取代码的位置发给AI，但不要发密钥本身。
