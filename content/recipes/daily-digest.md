## 你会做出什么

每天早上固定时间，你的邮箱里收到一封邮件：昨天到今天，你订阅的几个信息源有什么新内容，按来源分好组，每条有标题、链接和两行摘要。

它不依赖你的电脑开机。脚本放在GitHub上，由GitHub Actions按时间表自动运行。你做的是三件事：选信息源、写脚本、配好定时和邮箱。做完之后，它每天自己跑。

这是[定时任务](/words/script)的入门项目，也是理解「程序可以自己醒来干活」的最短路径。

## 开始前准备

- 会用Git和GitHub，见[第3关](/start/go-live)。
- 会安装Python并运行脚本，见[Excel合并项目](/projects/excel-merge)的做法，注意用虚拟环境。
- 3到5个你真正想看的信息源。第一版**只用有RSS/Atom订阅地址的源**：很多博客、新闻站、GitHub的发布页都有。不要上来就去爬没有提供订阅的网页，那要考虑对方网站的规则，也更容易坏。
- 一个收件邮箱，以及一个发件方式（下面选一个）：
  - 国内常用：QQ邮箱的SMTP服务。需要在邮箱设置里开启POP3/SMTP服务，生成「授权码」（不是QQ密码），服务器地址常见为`smtp.qq.com`，端口465（SSL）。这些参数以QQ邮箱帮助中心的最新说明为准。
  - 海外：Resend等邮件服务。截至2026年11月，Resend定价页写明免费计划为每月3000封、每天100封、3个域名；但给别人发信通常要先验证自己的域名，具体限制以其官方文档为准。
- （可选）一个大模型API Key，用来生成摘要，见[第5关](/start/add-ai)。不用也行，第一版直接用原文开头。

> [!warn]一个没法回避的不确定：GitHub Actions的运行机器在海外，QQ邮箱是否会拦截来自海外IP的登录，没有通用的结论。所以第3步让AI先做一次最小的「发信测试」，通了再往下。万一被拦，备选是换成海外邮件服务，或者在自己的电脑上用系统定时任务运行（电脑需要开机）。

## 第1步：先抓取和整理，不发邮件

```prompt 复制给AI
我是不会写代码的人，想做一个「每日摘要」小工具：每天读取几个RSS源，整理成一封邮件。现在只做第一步：抓取并生成摘要文本，不发邮件。

先用5行以内说明计划，有拿不准的先问我，没有就直接做。

要求：
1. Python脚本digest.py，依赖装在项目内的虚拟环境`.venv`，并生成requirements.txt。请优先使用成熟的库（如feedparser）读取RSS，先去库的官方文档确认用法。
2. 信息源写在单独的sources.yaml（或json）里：名称、RSS地址。我的信息源是：（列出3到5个名称和RSS地址，不确定地址的告诉我，你帮我找并和我确认）。
3. 只保留最近36小时内发布的条目（按条目发布时间，时区正确处理）。没有发布时间的条目，按网站默认行为处理并告诉我。
4. 每个信息源最多8条，条目：标题、链接、摘要（先用原文摘要前120字，去掉HTML标签）。
5. 某个源抓取失败（超时、404）不影响其他源，并在摘要末尾列出「抓取失败的源」。设置请求超时15秒，并带上说明身份的User-Agent。
6. 输出两个文件：digest.html（用于邮件正文，行内样式，宽度600px以内，手机可读）和digest.txt（纯文本备份）。
7. 同一条目（链接相同）不重复出现。
验收：运行后用浏览器打开digest.html检查排版；故意加一个错误地址的源，确认其他源仍正常。如实报告。
```

你会看到：运行`digest.py`后，生成`digest.html`，浏览器打开就是摘要排版。

如果不对：缺库见[python-module-not-found](/fix/python-module-not-found)，Mac上pip报错见[pip-externally-managed](/fix/pip-externally-managed)，网络超时见[fetch-failed](/fix/fetch-failed)。

## 第2步：发邮件（先在本机测通）

邮箱密码和授权码**绝对不能写进代码**。用环境变量，见[env-var](/words/env-var)。

```prompt 复制给AI
请给digest.py增加发邮件功能（用Python标准库smtplib和email）：
1. 配置全部从环境变量读取：SMTP_HOST、SMTP_PORT、SMTP_USER、SMTP_PASSWORD、MAIL_TO。代码里不出现任何账号密码。本地用`.env`文件，并确认`.gitignore`已包含`.env`。
2. 邮件主题：「每日摘要 · 年月日」；正文为digest.html，同时附带digest.txt作为纯文本备选。
3. 默认使用SSL连接（端口465）；连接失败、认证失败给出明确的中文提示，并说明常见原因（如授权码填错、没开启SMTP服务）。
4. 增加`--test`参数：只发一封内容为「测试邮件」的短邮件，用来检验邮箱配置。
5. 增加`--dry-run`参数：只生成文件不发信。
先帮我写好步骤：我应该如何获取QQ邮箱的授权码（请你去官方帮助中心确认最新步骤，不确定的告诉我）。我自己填好`.env`后，你运行`--test`，告诉我结果。
```

你会看到：收到一封「测试邮件」。收不到先看垃圾邮件箱。

> [!tip]密码泄露的后果比你想的严重。如果授权码或Key不小心提交到了GitHub，立刻去邮箱作废它并重新生成，见[secret-leaked](/fix/secret-leaked)。

## 第3步：让它每天自动运行（GitHub Actions）

```prompt 复制给AI
请用GitHub Actions让digest.py每天自动运行。
1. 创建`.github/workflows/daily-digest.yml`：触发方式包括定时（schedule）和手动（workflow_dispatch，方便我随时点一下测试）。
2. 我希望每天北京时间早上7:00发送。注意GitHub的定时任务默认使用UTC时间，请换算并在注释里写明；并告诉我官方文档说定时任务在高负载时可能延迟，所以实际到达时间会有偏差。不要把时间设在整点，请用官方文档建议的方式减少延迟。
3. 步骤：检出代码 → 安装Python和requirements.txt → 运行digest.py。邮箱配置通过GitHub仓库的Secrets传入，不写在文件里。
4. 告诉我应该在GitHub网页的哪里添加Secrets，需要添加哪几个，逐个列出名称。
5. 说明：公开仓库里的定时任务，在仓库连续60天没有活动时会被GitHub自动停用，请告诉我怎么发现和恢复。
然后带我推送到GitHub，并手动触发一次，看结果。
```

你会看到：在GitHub仓库的Actions页面，手动运行后出现绿色对勾，邮箱收到当天的摘要。

如果不对：

- 红色叉：点进去看哪一步失败，把日志发给AI。
- 本机能发、Actions里发不出：就是前面提到的海外IP问题，换发信服务，或改用自己电脑运行。
- 没有触发：定时触发不是准点的；官方文档写明最短间隔是5分钟，并可能延迟。

## 第4步（可选）：用大模型把摘要写得更好

```prompt 复制给AI
请增加可选功能：如果设置了环境变量LLM_API_KEY，则把每个来源的条目交给大模型生成一段3句话的「今日看点」，放在邮件最前面；没设置就跳过。
要求：1.调用方式和模型名请按我所用服务商（填写）的官方文档确认。2.提示词里要求「只依据我提供的条目内容总结，不得补充条目里没有的信息」。3.控制成本：每次最多发送前40条条目的标题和摘要；失败时跳过，不影响邮件发出。4.在邮件末尾注明「看点由AI生成，请以原文为准」。5.把LLM_API_KEY同样放进GitHub Secrets。
```

## 怎么验收

- Actions页面手动运行成功，邮箱收到邮件，排版在手机上可读。
- 连续三天，早上邮件自动到达，不是你手动点的。
- 故意把一个信息源改成错误地址，邮件仍然发出，并在末尾标明哪个源失败。
- 仓库里搜索不到任何密码、授权码、Key，Git历史中也没有。
- 链接可点，条目不重复。

## 可以继续加的功能

- 关键词过滤：「只保留标题或摘要包含这些关键词的条目：……」
- 按重要度排序：「让AI给每条打1到5分的相关度，只保留4分以上。」
- 更多来源：「增加一个获取天气或日程的区块。」
- 发给多个人：「MAIL_TO支持多个收件人，并给每个收件人提供退订方式。」群发要考虑合规和送达率。
- 换成Vercel的定时功能：官方文档写明Hobby套餐的定时任务最短一天一次，触发时间在一小时范围内浮动，要精确时间需要付费套餐，让AI评估是否值得迁移。

## 常见坑

- 把授权码写进代码并推到GitHub。
- 时区搞错：GitHub默认UTC，北京时间要提前8小时换算，导致邮件在半夜到。
- 以为定时任务一定准点。免费定时通常有几分钟到更久的延迟。
- 公开仓库长期没动静被停用，邮件突然不来了。
- 直接爬没有提供订阅的网页，容易在对方改版后失效，也可能违反网站规定。优先用RSS或官方API。
- 邮件被当作垃圾邮件。给自己发信问题不大，群发给很多人就需要正规的邮件服务和域名配置。
