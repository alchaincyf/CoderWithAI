## 你会做出什么

一个能玩的网页小游戏。这篇用「打砖块」做例子：底部一块挡板，一个球，上面一排排砖块，球碰到砖块就消掉并加分，球掉下去扣一条命，砖块打光就过关。

它的特别之处是「自定义主题」：砖块、球、背景、标题、过关文案，都集中在文件开头的一段设置里。想做成「给女朋友的情话打砖块」「公司团建版」「接水果改成接咖啡豆」，只改这段文字和颜色就行。

整个游戏是一个 `index.html`，双击就能玩，也能上线后发链接给朋友。如果你想做接水果，把第一条提示词里的玩法描述换掉就可以，其余步骤通用。

## 开始前准备

- 会用AI做出网页并在浏览器打开，见 [第2关](/start/first-page)。上线分享要走 [第3关](/start/go-live)，只自己玩可以不上线。
- 想好主题：游戏叫什么、砖块上写什么字（可以放祝福语、同事外号、单词）、过关后显示一句什么话。
- 不需要任何美术素材，第一版全部用色块和文字，这样最稳。

> [!why] 为什么游戏用色块而不是图片：图片要找素材、要处理版权、还要处理加载。先用色块把「好不好玩」验证了，再换皮。游戏的乐趣在手感，不在贴图。

## 第1步：做出一个能玩的版本

```prompt 复制给AI
我是不会写代码的人，想做一个网页版「打砖块」小游戏，自己玩，也想发给朋友。

请先用5行以内说明计划，有拿不准的先问我，没有就直接做。

要求：
1. 只做一个 index.html，使用 <canvas>，原生 JavaScript，不用任何框架和外部资源。
2. 玩法：底部挡板左右移动；球碰到墙壁、天花板、挡板、砖块反弹；砖块被打中消失并加 10 分；球掉出底部扣 1 条命，共 3 条命；砖块全部消失显示「过关」；命用完显示「游戏结束」并可点击重新开始。
3. 操作：电脑用键盘左右方向键，同时支持鼠标移动控制；手机用手指在屏幕上左右拖动。画布要自适应屏幕宽度，保持竖屏比例（比如 3:4），不能出现页面滚动或被浏览器下拉刷新干扰。
4. 砖块 5 行 8 列，不同行用不同颜色。球速度适中，每过一关球速略微提高。
5. 所有可自定义的内容放在文件最顶部的一个 CONFIG 对象里：游戏标题、背景色、球色、挡板色、各行砖块颜色、砖块上显示的文字列表（循环使用）、过关文案、失败文案。代码其他地方不写死这些内容。
6. 暂停：按空格键或点击右上角按钮暂停/继续。切换到别的浏览器标签页时自动暂停。

验收：
- 球在高速时不能穿过砖块或挡板（请你说明是如何避免「穿透」的）。
- 手机尺寸（375×667）下能完整显示、能拖动控制。
- 重新开始后分数、命数、砖块全部重置，不残留上一局状态。
- 控制台无报错。
做完请自己打开运行验证，如实告诉我你验证了什么、哪些必须由我亲手玩了才知道。
```

你会看到：浏览器里一个能玩的游戏。先别管好不好看，玩三分钟，记下所有「怪怪的」感觉。

如果不对：

- 球卡在挡板里来回抖：对AI说「球打到挡板侧面时会卡住抖动，请修复碰撞逻辑，球碰到挡板后位置要被推出到挡板之外」。
- 手机上拖动时页面跟着滚：对AI说「在canvas上禁用触摸的默认滚动行为」。
- 画布糊：这是高分屏的常见问题，对AI说「按devicePixelRatio处理画布清晰度」。

## 第2步：把手感调好

游戏好不好玩，七成靠手感。你玩过之后，用具体的话告诉AI：

```prompt 复制给AI
我玩了一下，感受如下，请逐条处理，并在 CONFIG 里增加对应的可调参数（带中文注释），这样我自己也能微调：
1. （例如）球太慢，前半局很无聊：把初始速度调快约 30%。
2. （例如）挡板有点窄，容易漏球：宽度加大。
3. （例如）球打到挡板不同位置，反弹角度应该不一样：靠边打出去更斜，打中间更直。
4. 打掉砖块有一点点反馈：砖块消失时有一个 0.15 秒的缩小动画。
请先告诉我每条你准备怎么改，再改，改完自己测试。
```

把括号里的例子换成你的真实感受。「太慢」「太窄」「不爽」这类话AI听得懂，不用懂碰撞原理。

## 第3步：换成你的主题

```prompt 复制给AI
请只修改 CONFIG，不要动游戏逻辑，把游戏做成这个主题：
- 游戏标题：
- 配色风格（描述即可，比如「复古街机，深蓝底，霓虹色砖块」）：
- 砖块上的文字（每行一条，建议2到4个字）：
- 过关时显示：
- 游戏结束时显示：
如果砖块上的字在小屏幕下放不下，请自动缩小字号，并保证最长的那条也能看清。
```

你会看到：同一个游戏，换了一身衣服。这就是把参数集中在CONFIG的好处。

## 第4步：加上最高分和音效

```prompt 复制给AI
请加两个功能：
1. 最高分：用 localStorage 保存历史最高分，显示在画面顶部，key 用 mini-game-highscore。
2. 音效：用浏览器的 Web Audio API 合成短促的「叮」声（碰砖块）和「咚」声（碰挡板、掉球），不使用任何外部音频文件。因为手机浏览器要求用户点击后才能发声，请在第一次点击/触摸「开始」时才初始化声音；再加一个静音按钮。
测试：刷新页面最高分仍在；静音时无声。
```

## 第5步（可选）：上线发给朋友

只是单个 `index.html`，上线最省事，按 [第3关](/start/go-live)推到GitHub再用Vercel部署。上线后自己用手机再玩一遍。

## 怎么验收

- 用电脑和手机各完整玩一局，从开始到过关，再玩一局到失败。
- 暂停、重新开始、静音都正常。
- 最高分刷新后还在。
- 找一个没见过它的人玩30秒，不告诉他规则，看他能不能看懂。看不懂的地方就是要改的地方。
- 改一次CONFIG里的标题和颜色，确认页面跟着变。

## 可以继续加的功能

- 道具砖：「有10%的砖块是道具砖，打掉后掉落，接住后挡板变宽10秒。」
- 关卡：「增加第2、3关，砖块排列成不同图案，图案用文本矩阵定义在CONFIG里。」
- 排行榜：要做多人排行榜就需要数据库，见 [第4关](/start/save-data)，难度升级。
- 接水果版：「把玩法换成接水果：物体从上方随机掉落，接到加分，接到炸弹扣命，速度逐渐加快。」
- 分享战绩：「游戏结束时生成一张带分数的图片，可以长按保存。」

## 常见坑

- 一次性要求太多玩法，结果每个都半成品。先把一个核心循环玩顺，再加东西。
- 帧率问题：不同刷新率的屏幕上球速不一样。让AI按时间间隔而不是按帧数移动物体。
- 手机上点一下没声音，因为浏览器需要用户先交互。
- 游戏里用了别人的图片、音乐、角色，发出去可能涉及版权。做主题换皮时优先用自己的文字和纯色。
- 打开报错或空白，见 [blank-page](/fix/blank-page)。
