## 你会做出什么

在你电脑上运行的一个小脚本。你把几百个格式相同的Excel文件丢进一个文件夹，运行脚本，得到：

- 一个`合并结果.xlsx`，所有表的数据上下拼在一起，多一列「来源文件」，出了问题能追到是哪个文件。
- 一张「核对报告」，告诉你读了多少个文件、每个文件多少行、总共多少行、哪些文件有问题（打不开、表头对不上、空表）。

原始文件一个字都不会改。整件事在你电脑里完成，不上线，不上传，适合处理含内部数据的表格。

## 开始前准备

- 装好一个AI编程工具，见[第1关](/start/setup)。
- 电脑上有[Python](/words/python)。没有的话不用自己装，第1步让AI帮你检查。
- 一个测试文件夹：先从原始表里复制5到10个文件放进去练手，**别直接拿全部原件试**。
- 弄清楚你的表：每个文件是不是同样的列？数据是在第一个工作表，还是每个文件有好几个表？表头是在第1行，还是上面有标题、合并单元格？这几个问题决定脚本怎么写，请你先随手打开两三个文件看一眼。

> [!warn]本篇处理的是`.xlsx`文件。老格式`.xls`也能读，但需要额外的库，让AI按需处理。带密码的文件、`.xlsm`宏文件，先告诉AI，不要混在一起。

## 第1步：搭好环境，让AI看懂你的表

先在项目文件夹里建一个`原始表`文件夹放入测试文件，然后发：

```prompt 复制给AI
我是不会写代码的人，需要把很多个格式相同的Excel文件合并成一张表。我会让你写一个Python脚本，在我的电脑上运行。

先不要写脚本，请按这个顺序做：
1. 检查我电脑上的Python版本。需要的库（pandas、openpyxl）请装在项目内的虚拟环境 .venv里，不要装到系统环境，并告诉我每条命令是做什么的。
2. 读取「原始表」文件夹里的所有 .xlsx文件，只读，不修改任何文件。对每个文件报告：文件名、有几个工作表、第一个工作表的前5行内容。
3. 把你的发现用大白话告诉我：表头在第几行？各文件的列是否一致？有没有合并单元格、空行、隐藏的工作表？
4. 然后问我3个你需要确认的问题，我回答后你再写脚本。
```

你会看到：AI建了`.venv`，列出每个文件的概况。如果Mac报`externally-managed-environment`，说明装到了系统环境，见[pip-externally-managed](/fix/pip-externally-managed)；以后提示缺库见[python-module-not-found](/fix/python-module-not-found)。

这一步的价值在于：让AI先看数据，再动手，避免它凭想象写一个只适合「理想表格」的脚本。

## 第2步：写合并脚本

回答完AI的问题后，发这条（括号里换成你的实际情况）：

```prompt 复制给AI
请写merge_excel.py，要求：
1. 读取「原始表」文件夹下所有 .xlsx（不含子文件夹；跳过以~$ 开头的临时文件），每个文件只读第一个工作表，表头在第（填：1）行。
2. 所有数据上下拼接，最前面加一列「来源文件」（文件名，不含路径）。
3. 所有列按文本读取（dtype=str），不让pandas自作主张改类型：身份证号、手机号、以0开头的编号必须原样保留。
4. 表头检查：以第一个有效文件的表头为准，其他文件如果表头不一致（缺列、多列、顺序不同），不要硬拼，放进「问题文件」清单并写明原因；顺序不同但列名一致的，按列名对齐。
5. 某个文件打不开（损坏、加密）时，记录原因并继续处理其他文件，不能让整个脚本中断。
6. 完全空白的行直接丢弃，并统计丢弃了多少行。
7. 输出到「输出」文件夹：
   - 合并结果.xlsx（一个工作表）
   - 核对报告.xlsx：第一页「汇总」（文件总数、成功数、问题数、各文件行数之和、合并后总行数、丢弃空行数），第二页「明细」（每个文件的行数），第三页「问题文件」。
8. 运行时在终端打印进度（第几个/共几个），结束时打印汇总。
9. 脚本顶部用常量写清楚输入文件夹、输出文件夹、表头行号，方便我改。

验收：用「原始表」里的测试文件运行，然后你自己用另一种方式（比如分别读取每个文件统计行数）核对：各文件行数之和 = 合并结果行数 +丢弃的空行数。把核对过程和结果告诉我。
```

运行命令一般是：

```bash
.venv/bin/python merge_excel.py
```

Windows上是`.venv\Scripts\python merge_excel.py`，AI会按你的系统告诉你确切写法。

你会看到：终端滚动打印进度，`输出`文件夹里出现两个文件。

如果不对：

- 报`PermissionError`：输出文件正在被Excel打开，先关掉，见[permission-denied-file](/fix/permission-denied-file)。
- 手机号变成科学计数法：第3条的文本读取没落实，让AI检查。
- 合并后行数对不上：把核对报告里的问题文件列表发给AI，让它逐一解释。

## 第3步：自己验证，别只信脚本

合并出错最危险的地方在于「看起来对」。抽查三处：

1. 打开`核对报告.xlsx`，看汇总：总行数是否等于你心里的估计。
2. 随便挑3个原始文件，在合并结果里用「来源文件」筛选，对比行数和前后几行内容。
3. 看合并结果的最后一行，是不是最后那个文件的最后一行。

```prompt 复制给AI
请写一个独立的校验脚本verify_merge.py，不复用merge_excel.py的读取逻辑：随机抽取10个原始文件，逐行逐列对比它们在合并结果中的内容，输出「一致/不一致」和不一致的具体位置。
```

## 第4步：换成真实数据运行

确认无误后，把全部原始文件放进`原始表`，再运行。几百个文件通常需要几十秒到几分钟，取决于文件大小。运行时间超过几分钟时，让AI在后台运行并定期报告进度，别干等。

## 怎么验收

- 核对报告里：成功数 +问题数 = 文件总数。
- 各文件行数之和 = 合并行数 +丢弃空行数。
- 抽查的3个文件，内容与原文件逐行一致。
- 身份证号、手机号、编号没有被改写（尤其是前导0和长数字）。
- 原始文件夹里的文件修改时间没有变化。

## 可以继续加的功能

- 读所有工作表：「每个文件读取所有工作表，并增加一列『来源工作表』。」
- 子文件夹：「递归读取子文件夹，『来源文件』列显示相对路径。」
- 去重：「根据『编号』列去重，保留最后一条，并把被去掉的重复行输出到单独的工作表。」
- 一键运行：「做成双击即可运行的脚本，运行结束后自动打开输出文件夹。」
- 小界面：「做一个网页界面，选择文件夹后点按钮合并，仍然在本机运行。」

## 常见坑

- 表头里有合并单元格或标题行，不处理就会拼出一堆「Unnamed」列。第1步让AI先看数据，就是为了发现它。
- 日期列：Excel里显示2024/5/1，读出来可能变成数字或时间戳。让AI说明它怎么处理日期，并核对。
- 文件名里有`~$`开头的文件，是Excel打开时产生的临时文件，不是真数据。
- 把这些表格发给在线AI之前，想一想数据是否敏感。本方案里只有脚本是AI写的，数据没离开过你的电脑，但你在对话里粘贴的表头和样例行会发给AI服务商，敏感内容请脱敏。
- 想用公式汇总而不是合并，那是另一件事，用Excel自带的功能更合适。
