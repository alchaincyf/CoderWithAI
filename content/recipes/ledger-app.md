## 你会做出什么

一个网页版记账本：用邮箱和密码注册、登录；记一笔账（金额、分类、日期、备注）；看本月的支出合计和分类占比；修改、删除；退出再登录或换手机登录，数据还在。

最关键的是：**每个人只能看到自己的账**。这不靠前端藏起来，而是靠数据库层面的规则（RLS，行级安全）强制执行。这是第4关的核心，也是做带登录应用最容易出事的地方。

## 开始前准备

- 完成[第3关](/start/go-live)，会推送、会部署。
- 读过[第4关](/start/save-data)，大致明白数据库、登录和密钥。
- 一个[Supabase](/words/supabase)账号和一个新项目。截至2026年11月，官方定价页写明免费计划为2个活跃项目、500MB数据库、5万月活用户，免费项目一周不活跃会被暂停。以官方页面为准。
- 国内读者：Supabase是海外服务，国内网络访问可能不稳，请上线后用国内网络实测。
- 在Supabase后台找到：Project URL和可公开使用的API Key（界面可能叫publishable key或anon key）。**不要用service_role密钥**。

> [!warn] Supabase自带的邮件发送服务有很低的限额：官方文档写明内置服务每小时仅2封邮件，要提高需配置自己的邮件服务。这意味着开启「邮箱验证」后，你自己试几次注册就会被限流。开发测试阶段，可以在Supabase后台的Authentication → Sign In / Providers里找到邮箱登录的设置，关闭「Confirm email」。正式给别人用之前，再配置邮件服务并打开。菜单名称以实际界面为准。

## 第1步：设计数据，先不写代码

```prompt 复制给AI
我是不会写代码的人，想用Supabase做一个带登录的记账本网页。我已经创建了Supabase项目。

先不要写网页，请只给我数据库方案，用我能看懂的话：
1. 表expenses：id、user_id（关联auth.users，默认值是当前登录用户）、amount（金额，用numeric，单位元，保留两位小数）、category（分类，文本）、note（备注，可空）、spent_on（日期）、created_at。
2. 开启行级安全，并写四条策略（查询、新增、修改、删除），每条都限制「只能操作user_id等于当前登录用户的行」。官方文档推荐把auth.uid()写成(select auth.uid())，请按官方文档确认写法。
3. 给user_id和spent_on建索引。
4. 给我完整的SQL，让我粘贴到Supabase的SQL Editor运行；再逐条解释。
5. 告诉我如何验证RLS真的生效：用两个不同账号，各记一笔，互相看不到。
```

你会看到：一段SQL加解释。粘贴进Supabase的SQL Editor点运行，Table Editor里出现`expenses`表，并显示RLS已启用。

如果不对：运行报错，把完整报错贴给AI，通常是表名或引用写错。

## 第2步：做登录注册页

```prompt 复制给AI
请做记账本网页的登录部分。项目URL是（填写），可公开key是（填写）。

要求：
1. 不用构建工具：用supabase-js官方的浏览器版本，下载到项目的vendor文件夹里本地引用，不依赖外部CDN（国内CDN有时不稳）。请先告诉我你下载的版本号和来源。
2. 页面index.html：未登录时显示登录/注册表单（邮箱、密码、切换按钮）；登录后显示记账界面（下一步做，现在放一个「欢迎，邮箱」和「退出」按钮）。
3. 用supabase.auth.signUp和signInWithPassword，请按Supabase官方文档确认写法。刷新页面后保持登录状态。
4. 错误信息显示中文：密码太短、邮箱已注册、密码错误、网络错误等。
5. URL和key放文件顶部常量，并注明这个key可公开，但service_role不行。
验收：注册→刷新仍登录→退出→再登录，全部成功；Supabase后台Authentication的Users里能看到该用户。请自己测试能测的部分，如实告诉我哪些需要我手动操作（比如邮箱验证）。
```

你会看到：注册后Supabase的Users列表里出现你的邮箱。

如果遇到`Email rate limit exceeded`，就是上面提到的邮件限额，按提示框处理。

## 第3步：记账、列表、修改、删除

```prompt 复制给AI
请完成登录后的记账界面：
1. 顶部：选择月份（默认本月），显示该月支出合计。
2. 记账表单：金额（只能是正数，最多两位小数）、分类（下拉：餐饮、交通、购物、居家、娱乐、医疗、其他）、日期（默认今天）、备注。提交写入expenses表。user_id不要由前端传，由数据库默认值决定。
3. 列表：按日期倒序显示所选月份的账目，每条可以编辑和删除（删除要二次确认）。
4. 分类汇总：用纯CSS画横向条形图，显示各分类占比，不引入图表库。
5. 手机优先，金额输入使用数字键盘。
6. 所有数据库操作失败时都给出提示，不能静默失败。
验收：增删改都能成功；刷新后数据仍在；换一个浏览器登录同一账号，数据一致；用第二个账号登录，看不到第一个账号的账目。把你的测试结果告诉我。
```

你会看到：一个可用的记账本。关键测试是最后一条：注册第二个账号，看到的应该是空白账本。如果能看到别人的账，立刻停下，说明RLS没配对，见[supabase-rls](/fix/supabase-rls)。

## 第4步：上线，并配置回跳地址

```prompt 复制给AI
请带我上线这个记账本：
1. 检查项目里有没有不该提交的内容（service_role密钥、.env、私人数据）。
2. 提交到GitHub并在Vercel部署，这是纯静态站点。
3. 部署完成后，告诉我需要到Supabase后台的哪个设置里，把线上网址填进Site URL / Redirect URLs，否则邮件验证链接会跳回localhost。
一步一步来，每步等我确认。
```

上线后，用手机再注册一个账号，记一笔；回电脑用同一账号登录，应该能看到。

## 怎么验收

- 换设备登录，账目一致。
- 两个账号互相看不到对方的数据（这是底线，不是加分项）。
- 前端代码、Git历史里没有service_role密钥。
- 用浏览器开发者工具的网络面板看请求，确认没有发出任何带别人user_id的请求就能成功的操作。你可以让AI解释为什么即使有人篡改请求，RLS也会拒绝。
- 退出登录后，刷新页面不会再显示账目。

## 可以继续加的功能

- 预算：「每个分类可设月预算，超出时进度条变红。」
- 导出：「增加『导出本月账目为CSV』按钮，注意金额和日期格式。」
- 图表：「用折线图展示最近6个月的支出趋势，请告诉我为什么选择某个图表库，并本地引用。」
- 多币种与汇率：先让AI调研数据来源与准确性，再做。
- 做成可安装的应用：参考[习惯打卡配方](/recipes/habit-tracker)里的PWA做法。

## 常见坑

- 建了表没开RLS，或开了但没写策略：前者所有人可读写，后者谁也读不到数据。
- 把service_role放进前端。
- 邮件限额：测试时被限流，看起来像注册坏了。
- 忘记配置Site URL，验证邮件打开后跳到localhost。
- 免费项目一周不活跃被暂停，数据暂时无法访问，需要到后台恢复。
- 金额用浮点数存储会出现0.1+0.2这类误差。让AI用numeric，或用「分」为单位存整数。
- 线上缺少配置的问题，看[env-missing-in-production](/fix/env-missing-in-production)。
