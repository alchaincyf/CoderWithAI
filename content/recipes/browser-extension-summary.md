## 你会做出什么

一个装在你自己浏览器里的小插件。看到一篇长文，点一下工具栏上的图标，弹出一个小窗口：

- 先显示这篇文章的标题、字数和提取出的正文预览；
- 点「复制总结提示词」，把「请总结以下文章……」加正文一次复制好，粘贴到任何AI聊天里；
- 进阶：填上你自己的大模型Key，点一下直接在小窗口里出总结。

[浏览器插件](/words/browser-extension)比网页更直接地「长在」你的工作流里，这也是它适合入门的原因：不用上线、不用服务器，装进自己的浏览器就能用。

## 开始前准备

- 一个Chrome浏览器。Edge等基于Chromium的浏览器大多也能加载，具体以你的浏览器为准。
- 装好AI编程工具，见 [第1关](/start/setup)。会用AI做网页，见 [第2关](/start/first-page)。
- 进阶部分需要大模型API Key，见 [第5关](/start/add-ai)。基础部分不需要。
- 想一个你每周都会遇到的场景：长文章、公众号、技术文档、购物评价……为它设计，别做一个「什么都能总结」的东西。

> [!why] 一个背景知识：Chrome现在的扩展规范是Manifest V3（以下简称V3）。AI可能会给你写出旧版（Manifest V2）的代码，那在新版Chrome里加载会失败。所以我们的提示词里明确要求V3。

## 第1步：做出能提取正文的插件

```prompt 复制给AI
我是不会写代码的人，想做一个 Chrome 浏览器插件：点工具栏图标，弹出小窗口，显示当前网页的标题、正文字数和正文预览，并有一个「复制总结提示词」按钮。

请先用5行以内说明计划，有拿不准的先问我，没有就直接做。

必须遵守：
1. 使用 Manifest V3（manifest_version 为 3）。写代码前请打开 Chrome 官方扩展开发文档（developer.chrome.com/docs/extensions）确认当前写法，不要凭旧记忆写 V2 的 background page 或 chrome.tabs.executeScript。
2. 权限最小化：只申请 activeTab 和 scripting，不要申请 <all_urls> 或 tabs。说明为什么这样就够用。
3. 点击图标弹出 popup.html（action.default_popup）。弹窗打开时，用 chrome.scripting.executeScript 往当前标签页注入一个函数，提取：document.title、页面正文文本。
4. 正文提取：优先取 <article> 或 <main> 的文本，没有就取 body 文本，并去掉 script、style、nav、footer、广告类元素。最多保留前 12000 个字符，超出的在弹窗里提示「已截断」。
5. 弹窗显示：标题、字数、正文前 300 字预览。「复制总结提示词」按钮把这样的文本复制到剪贴板：「请用中文总结下面这篇文章：先给 3 句话的核心结论，再列 5 个要点，最后指出文章可能不够可靠或带有倾向的地方。文章标题：xxx。正文：xxx」，复制成功按钮显示「已复制」。
6. 在 chrome:// 页面、Chrome 应用商店页面等受限页面上，不会报错，而是在弹窗里提示「这个页面无法读取」。
7. 文件：manifest.json、popup.html、popup.js、popup.css，以及图标（16、48、128，用脚本生成纯色图标）。不用构建工具，不引入外部库。
8. 最后告诉我：如何在 Chrome 里加载这个插件，以及如何查看插件的报错。

验收：在一篇普通文章、一个单页应用网站、一个 chrome://extensions 页面上各测试一次，并报告结果。
```

AI会告诉你加载方式，官方教程里的做法是：

1. 在Chrome地址栏打开 `chrome://extensions`。
2. 打开右上角的「开发者模式」开关。
3. 点「加载已解压的扩展程序」，选择你的插件文件夹。

具体菜单文字以你的Chrome版本为准。加载后，点浏览器右上角的拼图图标，把插件「固定」到工具栏。

你会看到：打开一篇文章，点图标，小窗口里出现标题、字数和预览；点「复制总结提示词」后，去任意AI聊天框粘贴，就是一份可直接发送的总结请求。

如果不对：

- 加载时提示manifest错误：点插件卡片上的「错误」按钮，把原文发给AI。常见原因是写了V2的字段。
- 点了图标没反应或读不到正文：在 `chrome://extensions` 点插件的「Service Worker」或在弹窗上右键「检查」，看控制台报错。
- 改了代码没生效：在 `chrome://extensions` 页面点插件卡片上的刷新按钮，再重开弹窗。

## 第2步：把提取做得更靠谱

不同网站的正文结构差别很大，第一版提取不好是常态。这时别让AI泛泛地「优化提取」，给它具体失败的网站：

```prompt 复制给AI
插件在这个网页上提取效果不好：（粘贴网址）
现象：（例如：正文里混进了侧边栏的推荐文章 / 只提取到了一半 / 提取到的是评论区）。
请你：
1. 先打开这个页面，查看它的 HTML 结构，告诉我正文实际在哪个位置。
2. 改进提取逻辑，但要保持对其他网站的兼容：不要为这一个网站写死选择器，除非别无办法，那就把「特定网站规则」放在单独的一个配置对象里。
3. 修改后，用这个网址和我之前测试过的两个网页都再测一遍。
```

你会看到：每遇到一个烂网站修一次，提取逻辑逐渐稳健。这是真实的开发过程。

## 第3步（进阶）：接大模型，直接在弹窗里出总结

这一步会让你直面一个安全问题：插件是装在你自己电脑上的，Key存在你自己的浏览器里，只给自己用，是可以接受的做法；但**如果要把插件发给别人，就不能把你的Key打包进去**，需要像 [AI聊天机器人配方](/recipes/ai-chatbot)那样，搭一个服务端接口替你转发。

```prompt 复制给AI
请给插件增加「直接总结」功能，仅供我自己使用：
1. 增加设置页（options_page）：让我填入 API 地址、模型名、API Key，保存到 chrome.storage.local。Key 不写在代码里。设置页上明确提示「Key 保存在本机浏览器里，请勿把这个插件分享给别人」。
2. 弹窗里增加「直接总结」按钮：把标题和正文发给我配置的大模型（OpenAI 兼容格式），把返回的总结显示在弹窗里。请求在 popup 或 service worker 中发起，并在 manifest 里用 host_permissions 只声明我的 API 域名。请先去 Chrome 官方文档确认跨域请求在扩展里的规则，再告诉我你的做法。
3. 请求中显示「总结中…」，失败时显示可读的错误（Key 错误、额度不足、网络问题、正文太长），不要把 Key 显示在任何错误信息里。
4. 默认只发送前 12000 个字符。弹窗里提示「内容将发送给你配置的大模型服务商」。
5. 我的服务商是（例如 DeepSeek），请根据它的官方文档确认接口地址、请求格式和当前可用的模型名。
测试：Key 为空、Key 错误、正常三种情况，各一次，报告结果。
```

你会看到：设置页填好后，点「直接总结」，几秒后弹窗里出现总结。

注意：把整页内容发给第三方的大模型服务商，等于把页面内容交给了它。内网系统、网银、私人邮件、含个人信息的页面，不要用。

## 怎么验收

- 在三类页面（新闻文章、技术文档、公众号文章）上都能得到不是空白的结果。
- 受限页面不崩溃，有提示。
- 查看 `manifest.json`：权限里没有多余项，没有 `<all_urls>`。
- 设置页的Key不在任何代码文件里，也不在复制出去的文本里。
- 关掉浏览器重开，插件还在，设置还在。

## 可以继续加的功能

- 右键菜单：「选中一段文字，右键『总结选中内容』。」需要用到contextMenus权限，让AI说明。
- 快捷键：「增加键盘快捷键打开总结。」
- 总结风格选择：「弹窗里可以选择『一句话/要点/给小学生讲』，分别用不同的提示词。」
- 历史记录：「把最近20次总结的标题和结果保存在本机，可以查看和清空。」
- 上架到应用商店：需要开发者账号和注册费用，还要写隐私说明并通过审核，具体以Chrome网上应用店的官方说明为准，建议先自用一个月。

## 常见坑

- 请求权限过大，如 `<all_urls>`，会让你自己都不放心，上架审核也更严。
- 把Key打包进给别人的插件。
- 改了manifest之后要在 `chrome://extensions` 重新加载插件，只刷新网页没用。
- 动态加载的网页（单页应用）打开弹窗时，内容可能还没渲染完，导致提取为空。重试或让AI加入等待逻辑。
- AI总结可能出错、遗漏、编造细节，见 [hallucination](/words/hallucination)。重要内容要回原文核对。
