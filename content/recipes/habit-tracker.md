## 你会做出什么

一个打卡网页：列出你的几个习惯（比如「喝水」「读书20分钟」「早睡」），每个习惯一个大按钮，点一下就是今天完成；旁边显示连续打卡天数，下面是最近四周的小方格日历。

数据保存在你这台手机的浏览器里，不上传、不用注册。部署后在手机上选「添加到主屏幕」，桌面上就多一个图标，点开是全屏的，看上去和App没区别。

这是练「[localStorage](/words/localstorage)」和「[PWA](/words/pwa)」的好项目：一个小东西，没有后台，就能每天自己用。

## 开始前准备

- 会用AI做网页、会本地预览，见[第2关](/start/first-page)。
- 要装到手机，必须先上线（PWA要求HTTPS），见[第3关](/start/go-live)。
- 想好3到5个习惯。习惯越少越容易坚持，别一上来列十个。
- 一张方形图作图标，没有的话让AI生成一个纯色图标。

先弄清楚一件事：数据只在「这台设备上的这个浏览器」里。换手机、清除浏览器数据、换浏览器，打卡记录就没了。所以我们会做导出备份。

## 第1步：先做出能打卡的页面

```prompt 复制给AI
我是不会写代码的人，想做一个习惯打卡网页，自己每天用。

请先用5行以内说明计划，有拿不准的先问我，没有就直接做。

要求：
1. 单个index.html，样式和脚本写在里面，不用框架，不依赖外部网络资源。
2. 习惯列表：默认3个习惯「喝水」「读书20分钟」「早睡」。每个习惯一行，左边名称，右边一个大圆按钮，点击切换「今天已完成/未完成」，再点一次可以取消。
3. 每个习惯显示「连续N天」。连续的定义：从今天（若今天没打）或昨天往前数，每天都有打卡的天数。请把这个算法的规则用中文写在代码注释里。
4. 习惯下面显示最近28天的小方格，有打卡的填色。
5. 数据用localStorage保存，key用habit-tracker-v1，刷新页面不丢。日期按本机本地时间的「年-月-日」记录，不用UTC。
6. 手机优先，按钮点击区域不小于48px，浅色界面，一个主色。

验收：
- 点打卡后刷新页面，状态还在。
- 手动把电脑日期改成连续几天，连续天数计算正确（请你写一段测试代码验证这个算法：连续3天、中间断一天、今天未打但昨天打了，各一例，并告诉我结果）。
- 没有控制台报错。
```

你会看到：一个可以点的打卡页。点按钮，圆圈变色，刷新还在。要看数据长什么样：在浏览器按F12 → Application（应用）→ Local Storage，能看到`habit-tracker-v1`。

如果不对：点了没反应，让AI「打开控制台看有没有报错并修复」。刷新后状态没了，对AI说「请检查localStorage的读写代码，用控制台验证数据有没有写进去，并说明原因」。本地预览打不开的情况见[localhost-refused](/fix/localhost-refused)。

## 第2步：增删改习惯

```prompt 复制给AI
给打卡页加习惯管理：
1. 页面底部「管理习惯」按钮，进入后可以新增、重命名、删除习惯，也可以上下调整顺序。
2. 删除前要二次确认，并说明「历史记录也会一并删除」。
3. 习惯名最多12个字，不能为空，不能重名。
4. 所有数据变更都写回localStorage。
改完请自己测试：新增→打卡→重命名→删除，确认历史记录跟着习惯走，没有出现错位。
```

## 第3步：导出备份，防止数据丢失

```prompt 复制给AI
请加「导出/导入备份」功能：
1. 「导出」按钮：下载一个habit-backup-年月日.json文件。
2. 「导入」按钮：选择该文件，恢复数据。导入前提示「会覆盖当前数据，是否继续」，文件格式不对时给出明确提示而不是崩溃。
3. 导入时校验数据结构，不合法就拒绝。
测试：导出→清空数据→导入，确认完全恢复；再用一个随便改坏的json试一次，确认能友好报错。
```

> [!tip]养成习惯：每月导出一次，存到网盘。这是本机存储方案的代价，也是它不需要你注册任何账号的原因。想要换设备自动同步，要把数据放到云数据库，见[第4关](/start/save-data)和[记账本配方](/recipes/ledger-app)。

## 第4步：变成能装到桌面的PWA

```prompt 复制给AI
请把这个页面改造成可安装的PWA：
1. 添加manifest.webmanifest：名称、short_name、start_url为"./"、display为standalone、theme_color、background_color，以及192×192和512×512两个PNG图标。
2. 添加apple-touch-icon（180×180），因为iPhone添加到主屏幕会用它。
3. 在index.html里引用这些文件。
4. 添加一个最精简的service worker让页面离线可打开：只缓存index.html和图标，缓存名带版本号。并在代码注释里写清楚「以后改了页面如何让用户拿到新版本」。
5. 图标先帮我生成：用主色背景加白色对勾，用脚本生成PNG文件。
不要使用任何PWA框架。完成后告诉我怎么用Chrome开发者工具的Application面板检查manifest和service worker是否正常。
```

你会看到：开发者工具的Application → Manifest里能看到名称和图标，没有红色报错。

> [!warn]离线缓存用不好，会让你改了页面却一直看到旧版本。第一次排查这类问题时，在开发者工具里点Application → Storage → Clear site data再刷新。

## 第5步：上线并装到手机

推送到GitHub，用Vercel部署（见[第3关](/start/go-live)）。拿到网址后：

- iPhone：用Safari打开网址，点底部的分享按钮，选「添加到主屏幕」。
- 安卓：用Chrome打开，菜单里选「安装应用」或「添加到主屏幕」，具体文字因浏览器和系统而不同。

iPhone的网页应用没有安装弹窗，只能手动添加，这是系统的限制，不是你做错了。

## 怎么验收

- 桌面图标点开是全屏，没有浏览器地址栏。
- 打卡后完全关掉再打开，记录还在。
- 开飞行模式再打开，页面仍能显示。
- 导出备份后，在电脑浏览器里导入，数据一致。
- 连续7天，你真的在用。这是最重要的验收：做出来而不用，等于没做。

## 可以继续加的功能

- 每周统计：「在页面顶部加『本周完成率』，按习惯显示本周完成了几天。」
- 补打卡：「允许点击小方格，补记最近7天内某天的完成状态。」
- 提醒：网页的推送提醒依赖系统和浏览器支持，iPhone上限制多，需要先查清楚再做。可以让AI「先调研在我的手机系统上能否实现，再告诉我方案」。
- 深色模式：「跟随系统切换深色模式。」
- 激励语：「连续满7天时，显示一句鼓励的话，文案我自己提供。」

## 常见坑

- 以为数据在云端，换手机后全没了。所以第3步的导出不要省。
- 日期用了UTC，凌晨打卡算成前一天。让AI明确用本地时间，并测试跨午夜的情况。
- 没上线就想装到手机。PWA需要HTTPS，本机的localhost只能在电脑上用。
- iPhone用Safari以外的浏览器找不到添加入口，换Safari试。
- 部署后改了页面没生效，多半是service worker缓存，见第4步的提示框。
