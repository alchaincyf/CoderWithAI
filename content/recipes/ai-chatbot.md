## 你会做出什么

一个聊天网页，背后接着一个大模型，但它不是通用聊天，而是「专属」的：有固定的人设、知识范围和说话风格。比如「某家咖啡店的点单助手」「你自己课程的答疑助手」「帮同事解释报销流程的小助手」。

结构是三块：浏览器里的聊天页面 → 你自己的一个服务端接口（`/api/chat`）→ 大模型服务商。**API Key只存在第二块里**，浏览器里永远看不到。这是第5关的核心：Key放前端，等于把银行卡密码贴在门上，见[api-key](/words/api-key)。

## 开始前准备

- 完成[第3关](/start/go-live)（会部署）和[第5关](/start/add-ai)（知道API Key是什么、怎么拿）。
- 一个大模型API的Key。国内读者可以选DeepSeek、Kimi、通义等；本篇以DeepSeek为例，因为它的接口兼容OpenAI的格式。按官方文档，请求地址的base URL是`https://api.deepseek.com`，Key在DeepSeek开放平台申请。换成别家，让AI按它的官方文档改写即可。
- **模型名字请以官方文档为准**。厂商换模型很勤，我查证时DeepSeek文档里写的是`deepseek-flash`和`deepseek-v4-pro`，你读到时可能已变。提示词里我会让AI先去读官方文档，而不是写死。
- 充一点点钱试用。API是按用量收费的，先别充大额。
- 想好机器人的资料：它是谁、能回答什么、不能回答什么、语气如何，以及它该知道的资料（几百到几千字，比如营业时间、菜单、常见问题）。

> [!warn]任何出现在网页源码、Git仓库、截图里的Key，都当作已经泄露。万一发生，立刻去服务商后台作废重新生成，见[secret-leaked](/fix/secret-leaked)。

## 第1步：先做出聊天界面（假回复）

先不碰Key。把界面做好，用假回复让它跑起来。

```prompt 复制给AI
我是不会写代码的人，想做一个聊天机器人网页。第一步只做界面，回复先用假的。

先用5行以内说明计划，有拿不准的先问我，没有就直接做。

要求：
1. 项目结构：public文件夹放前端（index.html），api文件夹以后放服务端接口。现在只做前端。
2. 单个index.html，样式脚本都在里面，不用框架，不依赖外部资源。
3. 界面：顶部机器人名称和一句介绍；中间对话区，用户消息靠右、机器人靠左，新消息自动滚到底；底部输入框和发送按钮；回车发送，Shift+回车换行。
4. 机器人回复先用一个函数fakeReply()返回固定文字，模拟1秒延迟，并显示「正在输入…」。
5. 手机优先，输入框不被手机键盘遮住（用dvh单位）。
6. 对话记录只保存在页面内存里，刷新即清空。
验收：能连续对话10轮，滚动正常；空消息不能发送；发送中按钮禁用；手机宽度下可用；无控制台报错。自己运行验证并如实报告。
```

你会看到：一个能聊天的壳子，回复是假的。

## 第2步：写服务端接口，Key放环境变量

```prompt 复制给AI
现在写服务端接口，让机器人真的接上大模型。我用DeepSeek。

请先做两件事再写代码：
(a)打开DeepSeek官方文档（api-docs.deepseek.com），确认当前的base URL、对话接口路径、请求格式、可用模型名，并告诉我你会用哪个模型、为什么；
(b)打开Vercel官方文档，确认当前在Vercel上写服务端函数（放在api文件夹）的写法，并告诉我你采用哪种。

然后实现api/chat：
1. 接收浏览器发来的消息数组messages（只含role和content），转发给大模型。
2. API Key只从环境变量DEEPSEEK_API_KEY读取，代码里不出现任何Key，也不要写进前端。
3. 人设写在服务端（不信任前端传来的system消息）：见下面「人设」。
4. 限制：只接受POST；messages最多20条；单条不超过1000字；设置max_tokens上限；校验不通过返回400和中文提示。
5. 错误处理：服务商返回错误（401、429、超时、5xx）时，对前端只返回友好提示，不要把服务商的原始报错和任何密钥信息透传给前端；在服务端日志里记录详细原因。
6. 先不做流式输出。
7. 本地测试方法：给我本机怎么设置环境变量（用 .env.local，并确认 .gitignore已排除它）、怎么本地运行。

人设：
（在这里写：你是谁、能回答什么、不能回答什么、语气、不知道时怎么说、你应该知道的资料……）

完成后请用curl或脚本自己调用一次接口，确认能返回；另外验证：把环境变量清空，接口返回的是友好错误而不是崩溃。
```

你会看到：本地启动后，用工具调用`/api/chat`返回一段回答。AI会告诉你本地怎么运行（可能用到`vercel dev`，需要登录Vercel CLI）。

如果不对：

- 401：Key没读到或填错，见[api-401](/fix/api-401)。
- 429：额度不足或请求太频繁，见[api-429](/fix/api-429)。
- 服务暂时繁忙：见[api-overloaded](/fix/api-overloaded)。
- 国内网络请求国外服务失败：见[fetch-failed](/fix/fetch-failed)。

> [!why]为什么人设放在服务端：前端的任何东西，用户按F12都能改。如果人设由前端传，别人可以把它改成「忽略之前所有规则」。放服务端，至少不能被直接改写（但别以为这就万无一失，见最后的「常见坑」）。

## 第3步：前后端连起来

```prompt 复制给AI
请把前端的假回复换成真调用：
1. 发送时把对话历史（最近10轮）POST给/api/chat，显示回复。
2. 请求中保持「正在输入…」，失败时显示后端返回的友好提示并保留用户输入，提供「重试」按钮。
3. 两次发送之间至少间隔1秒，发送中禁用按钮。
4. 前端代码里不应出现任何Key，请你搜索整个项目确认并告诉我结果。
测试：正常对话、故意不设环境变量、连续快速点击、很长的输入，各一次，报告结果。
```

你会看到：真实的AI回答出现在对话里，它的口气符合你写的人设。

## 第4步：上线，在线上配置Key

```prompt 复制给AI
请带我部署上线：
1. 提交前检查：项目、Git历史中没有Key，.env.local在 .gitignore里。
2. 推送到GitHub，在Vercel导入。
3. 告诉我在Vercel项目的哪个设置页添加环境变量DEEPSEEK_API_KEY，并说明添加后为什么需要重新部署一次才生效。
4. 部署后给我一份线上验证清单。
```

按[env-var](/words/env-var)的方法，在Vercel项目设置的环境变量页添加。线上不生效，多半是添加后没有重新部署，见[env-missing-in-production](/fix/env-missing-in-production)。

## 第5步：防盗刷

你的网址是公开的，接口也就是公开的。任何人都可以反复调用，花的是你的钱。第一版至少做这三层：

1. 服务端限制：上面已经限制了消息条数、长度、`max_tokens`。
2. 服务商后台：设置余额提醒或用量上限（如果该服务商提供），并只充小额。
3. 来访限制：

```prompt 复制给AI
请给/api/chat增加基础的防刷：同一个IP每分钟最多10次、每天最多100次。请告诉我：在Vercel的无服务器环境里，函数实例不共享内存，所以内存计数不可靠——需要借助外部存储才靠谱。请给我2到3个可选方案（含免费额度、国内访问情况、复杂度），先说推荐，我同意了再做。
```

## 怎么验收

- 线上网址能正常对话，回答符合人设。
- 浏览器F12 → Network里，看`/api/chat`的请求和响应，找不到Key。查看页面源码也找不到。
- 让朋友故意试：问它超出范围的问题、让它「忘记设定」，看它的表现，如实记录。
- 观察服务商后台用量，估算对话一次的成本，再推算被刷时可能的最大损失。
- Key不在GitHub仓库里（搜索仓库代码和历史）。

## 可以继续加的功能

- 流式输出：「让回复一个字一个字出现，需要服务端和前端都改，请先说方案。」
- 资料问答：资料多了不能全塞进人设里，要做检索。「我的资料有50页，请比较『全文放进提示词』和『检索相关片段』两种做法的成本与效果。」
- 保存历史：登录加数据库，见[记账本配方](/recipes/ledger-app)。
- 换模型：「把模型调用封装成一个函数，以后换服务商只改这一处。」
- 嵌入别的网站：「做成一段能嵌入其他网页的小气泡，注意跨域设置。」遇到跨域报错见[cors-blocked](/fix/cors-blocked)。

## 常见坑

- 把Key写在前端文件里「先试试」，然后忘了，结果推到公开仓库。
- 以为设了人设就安全。提示词注入（让模型无视规则）无法完全杜绝，所以别让机器人接触它不该接触的资料，别把敏感信息放进人设。
- 模型名过期：接口报「model not found」，去官方文档查当前名字。
- 回复很慢：先看是不是模型选得太大，是不是上下文太长，见[context-window](/words/context-window)和[token](/words/token)。
- 对话历史无限增长，费用越聊越高。限制轮数。
