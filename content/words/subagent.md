## 一句话
子代理是主AI临时派出的助手。它有自己独立的[上下文窗口](/words/context-window)，干完活只把总结交回来，过程里读的大量内容不会塞进主对话。

## 打个比方
像你让助理去查一份很厚的资料，他读完只回报「重点是这三条」，你桌面不用堆满那几百页。

不贴切的地方：助理汇报时可能漏掉你关心的点，他看到的内容你也不一定看得见。而且助理也在花钱，每个子代理都有自己的请求，算入同一份用量。

## 你会在哪儿碰到它
- Claude Code内置了几种：Explore（只读，快速搜代码）、Plan（计划模式下做调研）、general-purpose（通用，能读能改）。
- AI说「我派一个子代理去看看」，或在终端里看到多个任务同时在跑。
- 你也可以自定义：在`.claude/agents/`（当前项目）或`~/.claude/agents/`（所有项目）放一份带说明的Markdown文件；直接让Claude帮你建也行。
- 官方文档说明：默认子代理还可以再派子代理，最多嵌套三层；同时运行上限默认20个。

## AI提到它时，你该怎么接
```prompt 复制给 Claude Code
请派一个只读的子代理去检查整个项目里有没有硬编码的密钥、密码或API Key。
要求：只读不改；只把「文件路径＋行号＋是什么类型的密钥」汇总给我，不要把密钥原文贴出来；
没发现就明确说没发现，并说明你查了哪些目录。
```

## 容易踩的坑
- 一上来就开一堆：用量会成倍增加，订阅额度更快用完。大范围搜索、跑测试、读日志这种「过程很啰嗦、结论很短」的活，才适合派出去。
- 子代理不知道你们聊过什么：交给它的任务要自带背景和验收要求。
- 以为它的结论一定对：关键结论要抽查。
- 让多个子代理同时改同一批文件：容易互相覆盖。
