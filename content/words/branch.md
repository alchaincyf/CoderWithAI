## 一句话
分支是项目的一条平行时间线。你在新分支上随便折腾，主线（通常叫 `main`）一点不受影响，满意了再合并回去。

## 打个比方
像写文章时先「另存为」一份副本去大改，改好了再把好的部分合进正稿；改砸了，副本一删，正稿完好无损。

不贴切的地方：「另存为」是复制整个文件，分支不复制，只记录不同之处，所以很轻。合并时如果两边改了同一处，会出现冲突，要人工选。

## 你会在哪儿碰到它
- 终端里出现 `git checkout -b new-feature` 或 `git switch -c new-feature`（新建并切换到分支）。
- 命令提示符或编辑器左下角显示当前分支名，如 `main`。
- GitHub上的Pull Request（合并请求），就是请求把一个分支并入另一个。
- 部署平台通常把 `main` 分支当作线上版本。

## AI提到它时，你该怎么接
```prompt 复制给 Claude Code
我要试做一个比较大的改动：把首页改成深色主题。我不确定效果好不好，所以不想动现有版本。
请先新建一个叫 dark-theme 的分支再动手，每个阶段提交一次。
做完后告诉我：怎么在本地看效果；满意时怎么合并回main；不满意时怎么扔掉这个分支。
```

## 容易踩的坑
- 不知道自己在哪个分支：以为在改试验版，其实直接改在了 `main` 上。动手前让AI先确认当前分支。
- 切换分支前有没提交的修改：可能带过去，也可能被拒绝，先提交或让AI处理。
- 合并冲突看到一堆 `<<<<<<<`：不要自己手动删，让AI解释两边各是什么再决定保留谁。
- 分支越开越多不清理：做完的合并后删掉，保持清爽。
