## 一句话
开发服务器是运行在自己电脑上的预览网站。你改一行代码，保存后浏览器自动更新，不用手动重新打包。

## 打个比方
像裁缝店里的试衣间镜子：边改边看，随时调整。真正出货（[构建](/words/build)、[部署](/words/deploy)）是另一回事。

不贴切的地方：试衣间里看到的和成品大体一致，但开发服务器里的页面为了方便调试做了很多额外处理，速度和成品不一样。

## 你会在哪儿碰到它
- 在项目文件夹的[终端](/words/terminal)里运行 npm run dev（具体命令以 package.json 里 scripts 为准）。
- 终端会打印一个地址，例如 http://localhost:3000，打开它就能看到页面，见 [localhost](/words/localhost)。
- 终端窗口要一直开着。按 Control+C 停止它。
- 改代码保存后，页面自动更新，这叫热更新。
- 构建出错、代码写错时，浏览器页面上会弹出带红色的错误浮层，终端里也有详细信息。

## AI提到它时，你该怎么接
```prompt
请帮我把这个项目在本地跑起来，并告诉我访问地址。如果启动失败，先别乱改代码，把失败原因用大白话告诉我。运行起来后保持它开着。
```

```prompt
页面和我刚才改的不一样，像是没更新。请排查是不是开发服务器的问题：是否在运行、是不是缓存、有没有报错，一项项告诉我。
```

## 容易踩的坑
- 关了终端窗口，网页就打不开了。
- 以为开发服务器里看到的就等于线上效果。有些问题只有构建后才会暴露，上线前要跑一次 build。
- 不止一个终端同时启动了它，占用了不同端口，你看到的可能是旧的那个，见[端口](/words/port)。
- 让 AI 在同一个终端里既启动服务又执行别的命令，服务会被占住。让 AI 开新窗口，或者放到后台。
