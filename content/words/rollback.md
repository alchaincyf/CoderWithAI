## 一句话
回滚就是把项目或线上网站退回到之前某个正常的版本。它是AI编程里最重要的后悔药。

## 打个比方
像电脑的「还原到昨天」。装了个新驱动整台电脑蓝屏，不用逐个排查，直接退回昨天状态。

不贴切的地方：回滚只能退回「已经存过档」的版本。你没[提交](/words/commit)的修改，回滚之后找不回来。数据库里的数据也不会跟着退。

## 你会在哪儿碰到它
- AI改了一大堆，页面白屏了，你想「回到上一版」。
- 线上刚发布就出问题，需要紧急恢复：在[Vercel](/words/vercel)等平台的部署记录里，可以选择把之前一次成功的部署重新设为线上版本。
- 终端里出现`git revert`、`git reset`、`git checkout`。

## AI提到它时，你该怎么接
```prompt 复制给 Claude Code
刚才这轮修改把页面弄坏了，我想回到上一个能用的版本。
请先不要执行任何回退命令，先做三件事：
1. 用`git log`列出最近5次提交，告诉我每次大概改了什么；
2. 告诉我现在有没有还没提交的修改，回退会不会丢；
3. 推荐一种最安全的回退方式（优先`git revert`，保留历史），并解释它和`git reset --hard`的区别。
我确认后你再执行。
```

## 容易踩的坑
- `git reset --hard`会直接丢弃没提交的修改，且很难找回。用之前让AI先说清楚会丢什么。
- 以为回滚了代码，线上就恢复了：线上要重新部署（或在平台回滚部署）才生效。
- 数据库的改动不会被代码回滚撤销。涉及改表结构或数据时，上线前先备份。
- 没有提交习惯，就没有可回滚的点。每次验收通过就提交一次。
