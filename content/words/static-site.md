## 一句话
静态网站是一堆现成的 HTML、CSS、JavaScript 和图片文件。服务器不用现场做计算，用户来了，直接把文件递过去。

## 打个比方
纸质宣传册。印好了，谁来都发同样的一份，所以又快又省事。相反，动态网站像点单现做的餐厅，每位客人拿到的不同。

不贴切的地方：静态不等于「不能动」。页面里的动画、点击交互，仍然可以靠 JavaScript 实现，只是内容不是服务器现场生成的。

## 你会在哪儿碰到它
- 个人主页、作品集、产品介绍页、文档站、活动落地页，大多是静态网站。
- GitHub Pages、Cloudflare Pages、Vercel 都能免费或低价托管静态网站，见[部署](/words/deploy)。
- AI 会说「导出为静态站点」。以 Next.js 为例，构建后会生成一个 out 文件夹或类似的输出，里面就是纯文件，见[构建](/words/build)。
- 需要登录、支付、用户提交数据的功能，静态网站自己做不了，要接[后端](/words/backend)或 [Serverless](/words/serverless)。

## AI提到它时，你该怎么接
```prompt
我要做的是：（描述）。请判断它能不能做成纯静态网站。如果可以，帮我选最合适的方案；如果有部分功能需要后端，告诉我最小的补充方案是什么。
```

```prompt
请把这个项目配置成静态导出，并告诉我构建后的输出文件夹在哪里、怎么在本地预览，最后怎么部署到（填写平台）。
```

## 容易踩的坑
- 想加评论、表单、登录，才发现静态站做不了。动手前就想清楚需要哪些动态功能。
- 静态导出时，用了需要服务器的功能，构建会报错。
- 线上看到旧内容：每次内容改了都要重新构建、部署，它不会自动变。
- 路径写成绝对路径或 file:// 才能用，部署到子目录后图片全部失效，让 AI 检查。
