## 一句话
Auth包含两件事：认证（你是谁，也就是登录）和授权（你能做什么，也就是权限）。AI说的「接一个Auth」，就是给网站加上账号体系。

## 打个比方
像小区门禁。刷门禁卡证明你是住户（认证），电梯再根据你住几楼只让你按自己那一层（授权）。

不贴切的地方：现实的门禁是物理的，网站的每个请求都要重新验证一次「你的卡还有效吗」，所以会出现登录状态过期。

## 你会在哪儿碰到它
- 你说「要有用户注册登录」，AI会提到邮箱密码登录、验证码登录、Google/GitHub登录（OAuth）。
- 代码里出现 `session`、`token`、`JWT`、`cookie`、`middleware`。
- 常见现成服务：[Supabase](/words/supabase) Auth、Clerk、Auth.js。国内产品还会涉及短信验证码、微信登录，这些需要对应平台的资质和审核，以各平台官方说明为准。

## AI提到它时，你该怎么接
```prompt 复制给 Claude Code
请给项目加登录功能，优先用现成的认证服务，不要自己手写密码加密。
要求：1. 邮箱加验证码或邮箱加密码均可，先告诉我你的选择和理由；2. 未登录访问「我的数据」页面要自动跳到登录页；3. 每个用户只能读写自己的数据；4. 做完教我用两个账号验证第3点。
```

## 容易踩的坑
- 自己手写登录：密码存储、找回、防暴力破解都有大量细节，用成熟服务更安全。
- 只在前端隐藏按钮：真正的权限判断必须在服务端或数据库层做，前端的隐藏任何人都能绕过。
- 密钥写进代码：登录服务的密钥属于[环境变量](/words/env-var)。
- 线上域名没配进回调白名单：第三方登录在本地正常、上线后报 `redirect_uri_mismatch`。
