## 一句话
Serverless 并不是「没有服务器」，而是你不用管服务器。你把一个小函数交给平台，有请求来时它才启动、运行、收费，没请求时不占资源。

## 打个比方
叫网约车，而不是买辆车自己养。用的时候叫来，用完走人，按次付费，不用管保养和停车位。

不贴切的地方：网约车的司机一直在路上，函数则要「冷启动」，隔了一阵第一次调用会慢一点。

## 你会在哪儿碰到它
- 在 [Vercel](/words/vercel)、Cloudflare Workers、AWS Lambda 以及国内云厂商都有。名字不同，意思一样。
- Next.js 项目里的 api 路由，部署到 Vercel 后常会变成 Serverless 函数。
- 适合的任务：接收表单、调用第三方 [API](/words/api)、藏起 [API Key](/words/api-key)、处理 [Webhook](/words/webhook)。
- 不适合的任务：运行很久的任务、需要一直保持连接的聊天室、体积很大的处理。
- 平台通常对单次运行时间、内存、代码体积有限制，具体数字因平台和套餐而异，以官方页面为准。

## AI提到它时，你该怎么接
```prompt
我要在网站里加一个功能：（描述，例如接收表单并发邮件）。请用 Serverless 函数实现，部署到（填写平台）。说明密钥放在哪里，怎么测试，以及它在免费额度下大概能用多久。
```

```prompt
线上的云函数偶尔很慢或超时。请帮我判断是冷启动、执行时间太长，还是调用的外部服务慢，并给出处理办法。
```

## 容易踩的坑
- 任务超过平台的时间限制被强行中断，没有完整的结果。长任务要拆分或换方案。
- 把数据存在函数的本地文件里。函数每次可能运行在不同的机器上，文件不会保留，数据要存在[数据库](/words/database)里。
- 被恶意刷请求，账单暴涨。公开的接口要有限流或校验，并看一眼平台的用量和预算上限设置。
- 本地和线上的运行环境不同，本地能跑线上报错。看[日志](/words/log)。
