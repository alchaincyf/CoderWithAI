## 一句话
一次commit，就是把你此刻选中的修改，打包成一个带说明的存档点，记进[Git](/words/git)的历史里。

## 打个比方
像写日记。每次写完一页，合上，写上日期和一句话概要。以后翻日记，一眼知道那天干了什么。

不贴切的地方：日记不能撤销，commit可以回到任意一次，所以「说明写得清楚」比「很少提交」更重要。

## 你会在哪儿碰到它
- AI说「我帮你提交一下」，终端里出现：

```bash
git add .
git commit -m "新增登录页面"
```

- 在GitHub上能看到一串提交记录，每条有一个类似 `a1b2c3d` 的编号（哈希），那就是存档点的编号。
- 常见提交说明写法：`feat:` 新功能、`fix:` 修bug。

## AI提到它时，你该怎么接
```prompt 复制给 Claude Code
这一轮改动我验收通过了。请帮我提交：
1. 先运行git status和git diff，用人话告诉我这次改了哪些文件、做了什么；
2. 确认没有.env、密钥或大文件被加进来；
3. 提交说明用中文，一句话说清这次做了什么。
提交完告诉我这次存档点的编号。
```

## 容易踩的坑
- 说明写成「update」「修改」：以后想回退时根本找不到对应哪一次。
- 一次提交塞了很多不相关的改动：出问题时无法只退回其中一件事。
- 提交了不该提交的东西：密钥进入历史后，仅删除文件是不够的，需要换新密钥。
- `git add .` 会把当前目录下所有修改都加进去，提交前先看一眼 `git status`。
- 提交只是存在你电脑上，没有备份到网络，要靠[push](/words/push)上传。
