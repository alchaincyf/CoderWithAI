## 一句话
Vibe Coding指凭感觉编程：用自然语言说出想要的东西，让AI写代码，自己看运行结果、再继续说，几乎不读代码本身。

## 打个比方
像和一个手艺很好的木匠聊天：你说「再圆一点」「颜色深一点」，他动手改。你不必知道怎么用刨子。

不贴切的地方：做桌子错了你一眼看得见，软件的错常常藏着，比如数据泄露、漏洞。你不看代码，就得靠验收和测试来兜底。

## 你会在哪儿碰到它
- 这个词是Andrej Karpathy在2025年初提出来的，后来成了「用AI做东西」的流行说法。
- 你在Claude Code、Cursor、Trae里描述需求并反复调整，就是在vibe coding。
- 它适合做原型、个人工具、小网站；涉及钱、隐私、很多人使用的产品，需要更多检查。

## AI提到它时，你该怎么接
氛围编程也要有章法：小步前进、每步验收、随时存档。

```prompt 复制给 Claude Code
我们按小步推进。每次只完成一个功能，完成后：
1. 告诉我怎么在浏览器里验证它；
2. 我说「通过」之后，你再做git提交；
3. 提交说明写清楚做了什么。
现在先做第一步：做出一个能输入文字并显示在页面上的最简单页面。
```

## 容易踩的坑
- 完全不验收，一路让AI叠加功能：最后谁也看不懂，一动就坏。
- 没有版本存档：见[提交](/words/commit)和[回滚](/words/rollback)。
- 把密钥、用户数据当小事：这是氛围编程最容易出事的地方，上线前让AI专门做一次安全检查，并自己看一遍。
- 遇到[幻觉](/words/hallucination)不自知：AI会编出不存在的库和命令，报错时把原文贴回去让它核对。
