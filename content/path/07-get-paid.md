## 这一关你要做成什么

把「做出来」推进到「有人用、能收钱、你知道发生了什么」。具体是四样东西：一个收款或预约的入口；一个让陌生人能找到你的办法；一个看访问数据的后台；一份你每周花半小时做的检查清单。

最后还有一段实话：大多数作品不会赚钱。这一关不保证你赚钱，保证的是你能在最少的浪费里，尽快知道这件事值不值得继续。

过关标准：有一个公开网址能收款或登记预约，Vercel或百度统计的后台能看到访问数据，你写下了一条「做到什么就继续、做不到什么就停」的标准。

## 先懂一件事

### 收钱的难点不在代码

技术上，收款就是三步：用户付钱、平台通知你的程序「付成功了」、你的程序给他开通权益。难的是前面那一步：谁有资格收钱。

像开店。装POS机（写代码）只要半天，办营业执照（资质）才决定你能不能开店。所以顺序是：先搞清自己能走哪条路，再写代码。反过来，最容易卡死在最后一步。详细的概念见[在线收款](/words/payment)。

### 先有人想要，再接支付

在你为收款花一个周末之前，先花一个晚上验证：有没有人愿意为这件事付钱，哪怕只是留下联系方式。很多作品死在这里，不是因为没接支付，而是根本没人要。

## 动手

### 第1步：先验证，用最低成本

让你的作品多一个入口：「想要，请通知我」或「预约，上线后优惠」，收集邮箱或微信号。这不涉及任何资质。配方见[等待名单落地页](/recipes/landing-waitlist)。

```prompt 复制给Claude Code或TRAE
请在我的作品首页加一个「预约」入口，用来验证有没有人想要。
上下文：我的作品是<一句话说明>，目标用户是<谁>，我想验证他们愿不愿意为<某个具体功能>付费。
要求：
1. 先说计划，等我确认再动手。
2. 一个表单：邮箱必填，「你最想用它解决什么问题」选填。提交后存进我的Supabase数据库，这张表必须开RLS，只允许插入，不允许匿名读取；给我SQL，我自己去后台运行。
3. 表单提交需要防刷：同一个来源短时间内不能重复提交，输入长度要限制。
4. 页面上用一句话写清楚：会拿他的邮箱做什么，什么时候联系他。
5. 不要放任何支付按钮和价格。
验收标准：我自己提交一条，在后台能看到；用脚本连续提交会被拦住。
```

你会看到：首页多了表单，Supabase里多了一张表，里面是你测试时提交的那一条。

如果看到别的：提交没反应，见[环境变量线上缺失](/fix/env-missing-in-production)，多半是线上没配好变量。

### 第2步：选收款路径（先读完再选）

先说一个现实：大陆没有营业执照的个人，正规的直接收款路径很少。下面分开讲。

#### 国内路径

路径A，通过平台代收。你不直接收钱，平台收，扣掉服务费后给你。

- 爱发电（afdian.com）：官方创作者FAQ写明收取赞助金额的6%，其中1%是支付手续费、5%是平台服务费，创作者拿94%；当月的赞助在次月1号进入账户余额，之后可随时提现。创作者需要通过平台的认证。实名和是否需要营业执照，以爱发电官方FAQ、提现页和规则的当前说明为准。
- 面包多：它在App Store的页面宣传「平均服务费3%」，这是宣传口径，具体规则请以官网和创作者后台为准。
- 小报童：抽成和提现规则以其官网公布的说明为准，注册前先看清楚。

平台适合：卖内容、卖资料、接受赞助、小额收费。不适合：你想做一个标准的会员系统，每个功能点都自己控制。

路径B，注册个体工商户或公司，再开通微信支付、支付宝。微信支付官方文档列出的主体类型是个体工商户、企业、事业单位、政府机关、社会组织，列表里没有「个人」。通常还要绑定已认证的小程序、公众号或App（见[在线收款](/words/payment)）。支付宝的门槛以支付宝开放平台官方说明为准。

个体工商户怎么办理、要多久、怎么纳税，各地做法不同，没有通用的统一说法，请咨询当地的政务服务窗口和税务部门。有一点可以确定：收入要依法申报纳税，这不是可以跳过的步骤。

不建议：用个人收款码当「系统」做商业收款，或者使用来路不明的第三方支付通道。会遇到封号和合规风险。

如果你的产品是iOS App里卖数字内容，通常要走苹果内购，苹果官方页面写明数字商品和服务的佣金是30%，符合小企业计划等条件的是15%，符合条件的订阅也是15%，见[App Store上架](/words/app-store)。

#### 海外路径

Stripe官方的可开户国家和地区名单不包含中国大陆，包含中国香港。也就是说，大陆个人和公司主体不能直接开Stripe账户。

很多人想要的是「Merchant of Record（记录商户，简称MoR）」：由平台作为法律上的卖家，替你处理各国的销售税、退款和拒付，你只管产品。目前能看到的选择，这一年的变化很大：

- Lemon Squeezy：官网横幅写明，已经不再接受新注册，将在2027年3月31日关闭，建议商家迁移到Stripe Managed Payments。所以新项目不要再选它。
- Stripe Managed Payments：Stripe官方的MoR方案。卖家所在地要在官方列出的范围内，亚太地区包括中国香港、日本、新加坡和澳大利亚，不含中国大陆。只能卖数字产品，如软件、电子书、在线课程；咨询、设计、开发这类专业服务和需要真人参与的一对一服务不行。更要注意：官方的客户限制名单里有中国，也就是说中国的买家不能通过它付款。
- Creem：自称是MoR。它的官方文档（docs.creem.io）里，收款账户页写有支付宝提现方式，面向中国大陆商户，单笔上限50000元人民币；支持国家表里也列有中国，提现走本地银行转账并带限额说明。但文档没有说明个人主体能不能做卖家、需要通过什么身份或企业认证、税务怎么处理，这些以Creem官方页面和客服为准。费率以官方定价页为准，本站不写具体数字。
- Paddle：面向软件和数字商品的卖家。能否向大陆卖家开户、怎么提现，以Paddle官网的当前说明为准。

结论要看你的情况。你是大陆个人、用户也在国内：海外收款的门槛高、变数多（主体资质、身份认证、税务），不建议作为第一选择，先走路径A。你的用户在海外：才值得研究这条路，比如Creem的官方文档显示有面向中国商户的提现方式，但个人主体能否入驻要以官方为准；也可能需要海外或香港的主体和银行账户。这一步涉及法律和税务，建议咨询专业人士，别指望AI替你判断。

#### 怎么选

| 你的情况 | 现实选择 |
|---|---|
| 国内用户，个人，想先试水 | 路径A平台代收，或先做预约 |
| 国内用户，想长期做，愿意办手续 | 个体工商户 +微信支付/支付宝 |
| 海外用户 | Stripe或MoR（如Creem），先去官方确认个人主体能不能入驻 |
| 暂时没想清楚 | 继续做第1步的预约，别接支付 |

你会看到：你能说出「我选哪条，为什么，还差什么资质」。

如果看到别的：每一条路都卡在资质上，那就在这一步停下，用预约和平台代收先跑起来，资质可以后补。

### 第3步：接入收款（先沙盒，再正式）

这一步涉及密钥和钱，提示词里要求AI每到关键节点就停。

```prompt 复制给Claude Code或TRAE
我要给作品加收款功能。我的情况是：<写清：个人/个体工商户/公司，人在国内/海外，卖什么，一次性付费还是订阅，大概定价多少>。我选定的收款方式是：<平台名>。
请严格按下面顺序，每一阶段结束都停下来等我回复「继续」：
阶段1，只调研不写代码：读该平台当前的官方接入文档，告诉我接入流程、需要的密钥种类、测试（沙盒）模式怎么用、费用怎么扣、退款怎么处理。引用你读到的文档网址。如果这个平台不适合我的情况，直接告诉我。
阶段2，方案：列出要新增的文件、数据库表（订单、权益），哪些密钥放服务端。
阶段3，实现，只用测试模式：下单、跳转支付、支付成功后平台通知我的服务端（webhook）、服务端校验通知的签名后才开通权益。
约束：
1. 所有支付密钥、webhook密钥只放服务端环境变量，永远不进前端代码，不进git。
2. 是否已付款，只以服务端收到并验证过的webhook为准，不能相信前端跳转回来的参数。
3. 数据库表必须开RLS，用户只能看自己的订单；写订单只能由服务端用秘密密钥完成。
4. 需要我去平台后台填的值，列成清单让我自己填，不要让我把密钥贴给你。
5. 在我明确说「切换到正式模式」之前，不要写任何正式环境的配置。
验收标准：用平台提供的测试卡或测试账号完整走一遍，付款成功后权益开通，伪造请求不能开通。
```

你会看到：AI先给你调研结果和一份「我需要在后台做什么」的清单，没有直接写代码。

如果看到别的：AI没读官方文档就开始写，让它回到阶段1。密钥不小心贴进了对话，立刻到平台里作废并重新生成，见[密钥泄露急救](/fix/secret-leaked)。

还有一件跟Vercel有关的事：Vercel免费的Hobby套餐，官方服务条款写明只能用于个人或非商业用途。你一旦开始收费，就应该升级到Pro。官方升级流程里写的开发者席位是每月每人20美元（2026年11月）。升级后你还能用Spend Management设置预算，到上限自动暂停生产部署。

### 第4步：让人找到你

#### SEO基础

SEO是让搜索引擎认得你的网站。最低限度做这几件：每个页面有清楚的标题和描述；有网站地图；允许搜索引擎抓取；页面打开不慢；内容有真实价值。

```prompt 复制给Claude Code或TRAE
请给我的网站做一次基础SEO整理。先说计划，等我确认再动手。
上下文：这是一个<一句话说明>的网站，目标用户会搜索<填几个他们可能搜的词>。
要求：
1. 为每个页面设置独立的title和description，不要全站一样；用Next.js官方推荐的metadata写法，先读本项目所装版本的文档。
2. 生成sitemap和robots。
3. 设置分享用的预览图和标题（Open Graph），让链接发到微信、X、小红书时有清楚的预览。
4. 检查：每页只有一个h1、图片有替代文字、没有把需要登录的页面放进sitemap。
5. 不要堆砌关键词，不要编造评价或数据。
最后告诉我：我需要手动去哪里提交网站地图。
```

你会看到：页面源代码里每页的标题和描述不同，网站有`/sitemap.xml`和`/robots.txt`。

之后你自己把网站提交到搜索引擎的站长工具：Google有Search Console，百度有百度搜索资源平台，入口以各家官方为准。收录和排名需要时间，不会立刻有效果，也没有人能保证排名。

#### 在公开场合做东西（Build in Public）

在小红书、即刻、X上，定期发你做这个东西的过程：今天做了什么、遇到什么坑、数据是多少、哪里做错了。别人愿意关注一个「正在做」的人，比关注一个「已经做完」的产品更容易。

几条经验原则（这是做法建议，不是统计结论）：

- 发真实的过程和数据，不夸大，不编造用户评价。
- 每次发一个具体的东西：一张截图、一个数字、一个失败，别发空话。
- 每周固定发一两条，比一口气发十条有用。
- 各平台对站外链接和营销内容有自己的规则，发之前读一遍平台规则。

#### 做一个能分享的东西

最有效的传播，是用户自己愿意发。给你的作品加一个「结果页」：用户用完后得到一张好看的、带你网址的结果图，或者一个能直接发给朋友的链接。比如第5关的总结功能，可以做成「分享这份总结」。

### 第5步：看得到数据

没有数据，你只能凭感觉。三个选择：

- Vercel Web Analytics：最顺手，适合已经部署在Vercel上的项目。在项目的Analytics页面点Enable，安装`@vercel/analytics`，把`Analytics`组件加到根布局，重新部署。Hobby套餐每月包含5万个事件，数据保留1个月；超出后采集会暂停，7天后可以恢复（官方文档，2026年11月）。自定义事件（比如统计「点击购买」）需要Pro。
- 百度统计：国内常用，适合面向国内用户的网站。注册后在站点管理里获取统计代码，装到页面里，具体步骤以百度统计官方为准。
- Google Analytics 4：功能全，但国内网络下访问可能不稳定，请自测。官方也提醒你需要自行遵守适用的隐私法规，并获取用户同意。

```prompt 复制给Claude Code或TRAE
请给我的网站接入访问统计。先说计划，等我确认。
选择：<填：Vercel Web Analytics /百度统计/ Google Analytics 4>。
要求：
1. 先读该工具当前的官方文档，按官方方式接入，引用文档网址。
2. 需要我在后台手动做的步骤（启用、复制统计代码里的ID）列成清单让我自己做。
3. 统计代码只放在公开页面，不要放在需要登录后才能看到的、含个人信息的页面里。
4. 页面底部加一句话说明本站使用访问统计，链到一页隐私说明，内容基于实际收集的数据，不要写没做的事。
5. 接入后告诉我怎么验证数据真的上报了。
```

你会看到：部署后你自己访问几次，过一阵后台出现访问量。

如果看到别的：后台一直没数据，先确认已启用、已重新部署，再看浏览器网络请求里有没有统计请求。

定三个数字就够：访问的人数；真正用了核心功能的人数；付了钱或留了联系方式的人数。这三个数字之间的比例，比任何一个绝对值都重要。

### 第6步：维护，每周半小时

作品上线后，最容易发生的不是爆红，是悄悄坏掉。给自己定一个固定时间，每周一次：

1. 看报错：注意，Vercel Hobby的运行日志只保留1小时（官方文档，2026年11月），所以不能周末才去翻。让AI把关键错误写进Supabase里一张errors表，每周统一看。
2. 看数据：三个数字比上周变化了没有。
3. 看额度：Supabase免费项目闲置一周会被暂停，用量有没有接近上限；模型平台余额和上限；Vercel的用量页。
4. 看用户反馈：邮件、私信、评论。
5. 选一个小改动：这周只改一件事，用AI做，在新分支上改，预览没问题再合并。

```prompt 复制给Claude Code或TRAE
请帮我整理这个项目的「每周维护清单」，并做两件事：
1. 评估现在的错误记录情况：服务端接口出错时是否有记录（不记录密钥和用户隐私原文）？如果没有，建议并在我确认后实现一个errors表，必须开RLS，只允许服务端写入。
2. 生成一份每周10分钟的检查清单，写成markdown放在项目的docs/weekly-check.md，包含：看哪几个后台、看哪几个数字、什么情况需要立刻处理、什么情况可以下周再说。
先说计划，等我确认再动手。
另外请检查：依赖有没有已知的安全更新？只列出来，不要自动升级。
```

你会看到：项目里多了一份清单文件和一个错误记录机制。

### 第7步：诚实的一段

本站没有可靠的统计数字，但可以合理地说：大多数作品不会赚钱。你可以不被这个吓到，因为做出来本身就已经让你学到很多东西；也别用这个当借口不去验证。

下面这些信号，说明值得继续：

- 有陌生人自己回来第二次，没有你催。
- 有人主动问你：能不能加某个功能，能不能提价、能不能买。
- 有人愿意付哪怕很小的一笔钱。一个陌生人付的一块钱，比十个朋友说「不错」更有价值。
- 有人自发把它转给别人。
- 你自己仍然愿意每周花时间做，而且越做越觉得有意思。

下面这些情况，说明该停下或者换方向：

- 你在自己事先定好的期限内认真做了发布和分享，回来的陌生人几乎为零。
- 所有的好评都来自熟人。
- 你对着它感到的只剩义务感。
- 它在亏钱，而你没有预算上限。

停不等于失败。你可以把它归档，写一篇复盘，把学到的东西用到下一个作品。具体的时间和数字由你自己定，关键是动手前就写下来：我给它多少时间，看哪三个数字，达不到就停。

## 验收：怎么知道真的成了

- 有一个公开网址，能登记预约或能付款（沙盒测试通过，或平台代收页已创建）。
- 后台能看到访问数据。
- 你写下了一份继续或停止标准，里面有时间和三个数字。
- 搜索引擎的站长工具里提交了网站地图。
- 有一份每周维护清单，你已经执行了第一次。
- 仓库里搜不到任何支付密钥或webhook密钥。

## 最常卡在这几个地方

- 域名绑定后打不开：见[域名不生效](/fix/domain-not-working)。
- 线上收不到支付通知，或服务端读不到密钥：多半是环境变量没配或没重新部署，见[环境变量线上缺失](/fix/env-missing-in-production)。
- 国内用户反馈网址打不开：见[Vercel在国内打不开](/fix/vercel-blocked-in-china)。
- 密钥泄露：见[密钥泄露急救](/fix/secret-leaked)。
- 调用支付平台接口返回401：密钥用错了环境，测试密钥用在了正式环境，或者反过来，见[401报错](/fix/api-401)。

```prompt 复制给Claude Code或TRAE
请在我的作品首页加一个「预约」入口，用来验证有没有人想要。
上下文：我的作品是<一句话说明>，目标用户是<谁>，我想验证他们愿不愿意为<某个具体功能>付费。
要求：
1. 先说计划，等我确认再动手。
2. 一个表单：邮箱必填，「你最想用它解决什么问题」选填。提交后存进我的Supabase数据库，这张表必须开RLS，只允许插入，不允许匿名读取；给我SQL，我自己去后台运行。
3. 表单提交需要防刷：同一个来源短时间内不能重复提交，输入长度要限制。
4. 页面上用一句话写清楚：会拿他的邮箱做什么，什么时候联系他。
5. 不要放任何支付按钮和价格。

```

接入收款：

```prompt 复制给Claude Code或TRAE
我要给作品加收款功能。我的情况是：<写清：个人/个体工商户/公司，人在国内/海外，卖什么，一次性付费还是订阅，大概定价多少>。我选定的收款方式是：<平台名>。
请严格按下面顺序，每一阶段结束都停下来等我回复「继续」：
阶段1，只调研不写代码：读该平台当前的官方接入文档，告诉我接入流程、需要的密钥种类、测试（沙盒）模式怎么用、费用怎么扣、退款怎么处理。引用你读到的文档网址。如果这个平台不适合我的情况，直接告诉我。
阶段2，方案：列出要新增的文件、数据库表（订单、权益），哪些密钥放服务端。
阶段3，实现，只用测试模式：下单、跳转支付、支付成功后平台通知我的服务端（webhook）、服务端校验通知的签名后才开通权益。
约束：
1. 所有支付密钥、webhook密钥只放服务端环境变量，永远不进前端代码，不进git。
2. 是否已付款，只以服务端收到并验证过的webhook为准，不能相信前端跳转回来的参数。
3. 数据库表必须开RLS，用户只能看自己的订单；写订单只能由服务端用秘密密钥完成。
4. 需要我去平台后台填的值，列成清单让我自己填，不要让我把密钥贴给你。
5. 在我明确说「切换到正式模式」之前，不要写任何正式环境的配置。
验收标准：用平台提供的测试卡或测试账号完整走一遍，付款成功后权益开通，伪造请求不能开通。
```
