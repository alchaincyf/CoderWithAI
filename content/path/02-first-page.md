## 这一关你要做成什么

你会做一个「我的个人小站」：一个网页，介绍你是谁、做过什么、怎么联系你。

做到下面四条就算过：

1. 双击就能在浏览器里打开这个网页。
2. 你按自己的意思让AI改过三轮，每一轮都改对了。
3. 你能用大白话说出AI这几轮分别干了什么。
4. 项目已经用Git存过档，并且有一份写给AI的项目说明书。

如果你不想做个人站，换成别的也行，比如给朋友聚会做一个邀请页（见[配方：邀请函](/recipes/invitation)）。本关的方法是通用的。

## 先懂一件事：先说计划，再动手

新手最大的损失，是AI一上来就闷头干了一大堆，结果和你想的不一样，又得全部推翻。

对策只有一个：每次都要求AI先说计划，你点头了它再动手。这叫[规划模式](/words/plan-mode)的思路，不管你用什么工具，一句话就能做到。

好的提示词有四样东西：

1. 上下文：这是什么、给谁看。
2. 约束：用什么技术、不要做什么。
3. 验收标准：怎么算做对了。
4. 流程：先说计划，等我确认。

你自己随口写一句「做个个人网站」，AI会替你补全所有选择，补出来的多半是你不想要的。上面这四样，就是你的验收单。

还有一个概念：你和AI的一整段对话，AI能记住的量是有限的，叫[上下文窗口](/words/context-window)。对话越长，它越容易忘前面的事。所以每个小任务做完就存档，一个任务不对劲就开新对话。

## 动手

### 第1步：建项目文件夹，打开AI

在桌面新建一个文件夹，叫 `my-site`。一个项目就是一个文件夹，所有东西都放里面。

国内线：在TRAE里用「打开文件夹」打开它，保持IDE模式。国际线：在终端里 `cd` 进去，运行 `claude` 或 `codex`（具体步骤见[第1关](/path/setup)）。

你会看到：文件夹是空的，AI的输入框在等你。

如果看到别的：输入框没反应或要求登录，回第1关检查。

### 第2步：第1轮对话，让AI先说计划

先想三个问题并写下：你想让谁看？想让他们记住什么？放几块内容？下面是一份示范，请把括号里换成你自己的：

```prompt
我想做一个「我的个人小站」，只有一个页面，介绍我自己。

背景：
- 我是（职业／身份），在做（正在做的事）。
- 看的人主要是（潜在客户／朋友／同行），手机上打开的可能比电脑多。

内容分四块：我是谁（两三句话）、我做过的三件事、我最近在学什么、怎么联系我。具体文字先用占位内容，我之后自己改。

约束：
- 只用一个 index.html 文件，样式写在同一个文件里，不要用任何框架，不要装任何东西。
- 不要联网加载外部资源，要保证双击文件就能在浏览器里打开。
- 不要使用我没有授权的图片，需要图的地方先用纯色块占位。

验收标准：
1. 双击 index.html 能在浏览器里正常显示。
2. 手机宽度（缩窄浏览器窗口）下文字不溢出、不需要左右滑动。
3. 页面有一个醒目的标题和四个清楚分开的区块。

请先不要写代码。先用不超过10行告诉我：你打算怎么做、会创建哪些文件、有哪些你不确定、需要我决定的地方。我回复「开始」之后你再动手。
```

你会看到：AI回一份短计划，大意是「我会创建index.html，分成四个区块，用响应式写法适配手机」，也许还会问你几个问题，比如想要什么配色。每次措辞都不同，这是正常的。

怎么办：如果它的计划里有你不认同的（比如它想用框架），直接回复「不用框架，只用一个文件」。满意就回复「开始」。

它建好文件后会告诉你做完了。打开网页：在文件夹里双击 `index.html`；或让AI替你打开：

```prompt
请用系统命令在浏览器里打开 index.html，并告诉我 Mac 和 Windows 各自用的是什么命令。
```

你会看到：浏览器里出现你的小站，样子朴素。这就对了，第一版本来就朴素。

如果看到别的：一片空白，见[页面一片空白](/fix/blank-page)。

### 第3步：第2轮，改外观

对着页面，先只挑一个方向改，别一次提十个。写你看到的问题和想要的感觉，不要写「好看一点」。

```prompt
我看了页面，想调整外观，请只改样式，不要动文字内容和结构：
- 整体改成温暖、安静的风格：背景用米白色，文字用深灰而不是纯黑。
- 标题字体加大，和正文的大小差距要明显。
- 每个区块之间留出更大的空白，不要挤在一起。
- 链接和按钮用一个统一的强调色（你选一个沉稳的颜色，并告诉我色值）。
先用3到5句话告诉我你打算怎么改，然后直接做。做完告诉我改了哪些地方。
```

你会看到：刷新浏览器（Mac按Command+R，Windows按Ctrl+R），配色和留白变了。

如果看到别的：没变化，多半是没刷新，或AI改到了别的文件，问它「你刚才改了哪个文件」。改出了你不喜欢的颜色，直接说「颜色换成偏蓝的」，同样的流程再来一遍。

### 第4步：让AI解释它干了什么

此时先停一下，别急着往下做。每隔一轮，让AI用人话复盘一次。你要的不是学会代码，而是知道哪里能改、改什么会坏。

```prompt
请用我这种完全不会写代码的人能听懂的话，解释 index.html 的结构：
1. 这个文件分成哪几个部分？每部分管什么？
2. 如果我想自己改页面上的文字，应该去哪里改？请指给我看是哪几行。
3. 如果我想改某个区块的颜色，应该去哪里改？
4. 有没有哪些部分是我最好别手动改的？
不要贴大段代码，用比喻讲。
```

你会看到：AI用类似「这个文件像一份表格：最上面是设置，中间是样式，下面是内容」的讲法回答。

如果看到别的：它回答得太专业，补一句「再用生活里的比方讲一遍，别用术语」。它说的行号和你的文件对不上，要警惕，这可能是[幻觉](/words/hallucination)，让它重新读文件再回答。

### 第5步：第一次存档

用Git存档，等于给当前状态拍一张快照。以后AI改坏了，能退回来。你不用背Git命令，会说这句话就行：

```prompt
请帮我把这个项目用 Git 存档：
1. 如果还不是 Git 仓库，先初始化。
2. 如果 Git 提示需要设置用户名和邮箱，先问我，不要自己编。
3. 把当前所有文件提交一次，提交说明写成「第1版：个人小站基础版」。
4. 最后运行 git log，告诉我存档成功了没有，并解释你做了什么。
```

你会看到：AI会在终端里运行几条命令，其中可能会问你许可。最后给你看一条记录，大意是有一次[提交](/words/commit)，说明里有你要求的那句话。如果Git要用户名和邮箱，AI会问你，你给自己的名字和常用邮箱即可。

如果看到别的：提示不是Git仓库，见[git-not-a-repo](/fix/git-not-a-repo)。如果你用TRAE而AI不能直接运行命令，让它把命令列给你，在编辑器自带的终端里粘贴运行。

### 第6步：第3轮，加内容并修一个问题

第3轮练习两件事：加东西，并提出你发现的问题。你自己翻一遍页面，找出一个真实的问题，比如手机宽度下某段文字太挤。把下面的括号换成你的实际情况：

```prompt
请做两处修改，一次只做这两处，别的不要动：
1. 在「怎么联系我」区块下面，加一个「友情链接」区块，放三个链接占位（文字写「朋友A」「朋友B」「朋友C」，链接先指向 #）。
2. 我发现（把窗口缩窄后，“我做过的三件事”那一块文字贴着屏幕边缘）。请修好它，并告诉我原因。
改完后，请你自己检查一遍：有没有影响到其他区块？把你检查了什么告诉我。
```

你会看到：页面多了一个区块，窗口缩窄时那一块也不再贴边。AI会汇报原因，比如「缺少左右留白」。

如果看到别的：它顺手把别的地方也改了，用[撤销AI的修改](/fix/undo-ai-changes)的方法退回，然后再说一次「只改这两处」。

做完这轮，再用第5步的句子存一次档，把提交说明换成「第2版：加友情链接并修手机排版」。

### 第7步：写一份给AI的项目说明书

AI每次开新对话都是「失忆」的，你要把规矩写下来。这份文件就是[AGENTS.md与CLAUDE.md](/words/agents-md)：Claude Code读 `CLAUDE.md`，Codex读 `AGENTS.md`。其他工具（包括TRAE）读哪个文件，请直接问它，我没有在官方页面核实。

```prompt
请阅读当前项目，为它写一份项目说明书，文件名叫 AGENTS.md，不超过40行，只写你从项目里确认过的事实：
1. 这个项目是什么（两句话）。
2. 怎么预览（双击 index.html）。
3. 文件结构。
4. 规矩：每次只改我要求的地方；改动前先告诉我计划；样式写在 index.html 里，不引入框架；不要联网加载外部资源；做完一件事提醒我存档。
然后再创建一个 CLAUDE.md，里面只写一行 @AGENTS.md，让 Claude Code 也能读到同样的规矩。
最后告诉我：你用的这个工具，会自动读取哪个文件？
```

你会看到：项目里多了两个文件。AI最后回答你的工具读哪个文件。

如果看到别的：你用的工具不读这两个文件，让它告诉你它支持的规则文件叫什么，改名即可。

最后再存一次档：「加入项目说明书」。

## 验收：怎么知道真的成了

- 双击 `index.html`，浏览器里能看到小站，四个区块在，窗口缩窄不溢出。
- 你能口头说出三轮分别改了什么：第1轮生成，第2轮改外观，第3轮加区块并修排版。
- 终端里运行 `git log`（或让AI运行），至少看到三次提交记录。
- 项目里有 `AGENTS.md`，你读得懂它在说什么。

## 最常卡在这几个地方

1. AI改着改着把别的地方改坏了：见[撤销AI的修改](/fix/undo-ai-changes)。关键是每个小阶段就存档。
2. 对话很长以后AI开始忘事、反复犯同一个错：见[上下文满了](/fix/context-full)。存档，开新对话，让它先读 `AGENTS.md`。
3. AI陷入循环，同一个错来回改：见[AI卡在循环里](/fix/ai-stuck-loop)。别再重复说同一句话，换角度描述，或让它先解释为什么没成功。
4. 不是Git仓库：见[git-not-a-repo](/fix/git-not-a-repo)。
5. 页面空白：见[blank-page](/fix/blank-page)。
